# Fractionate Everything 设计结论

本文面向作者和 AI 维护者，只保留 FE 分馏域的稳定设计结论。

本文不写审计过程、必要性论证、公式、阈值、执行频率、状态字段和代码级流程。具体机制细则见 `DESIGN_DETAILS.md`。如果细则需要改变本文结论，必须先修改本文。

## 1. 文档职责

- `DESIGN.md`：只写结论、方向、边界和禁区。
- `DESIGN_DETAILS.md`：写公式、阈值、触发条件、状态字段、数据表、代码入口和 UI 操作细节。
- 代码实现以 `DESIGN_DETAILS.md` 的具体规则为准，但不能违反本文的方向结论。
- 本文每个模块只保留“结论、修改方向、禁止事项”。

## 2. 总体方向

结论：保留“矩阵阶段 -> 时隧检索 -> 自动化分馏 -> 成长/堆叠/成就 -> 数据中心反馈”的核心闭环。

修改方向：

- FE 的主线是当前存档逐步修复旧文明能力，跨存档残留只降低重复劳动。
- 矩阵负责打开阶段入口，精馏负责提供阶段坐标，时隧检索负责发现配方和原胚，分馏塔负责把发现内容接入自动化。
- FE 能力仍然存在，但玩家不再通过主脑科技树研究获得；它们表现为异常信号、旧文明启动套件、文明恢复进度、协议恢复和塔型注册。
- 后续设计先判断模块目的和边界，再写细节和代码。

禁止事项：

- 不允许把 FE 做成 UI 菜单购买能力。
- 不允许让 FE 自定义能力继续表现为主脑科技树里的普通研究项。
- 不允许把补差、任务、市场或 UI 替代稳定产线。
- 不允许在 `DESIGN.md` 中堆砌审计过程和数值细节。

## 3. 资源层级

结论：保留残片、矩阵精华、记忆源点三层资源。

修改方向：

- 残片作为底层成长和补差材料。
- 矩阵精华作为阶段坐标和检索稳定材料。
- 记忆源点作为最高层非产线记忆锚点。
- 其它旧源点概念只允许作为存档兼容占位。

禁止事项：

- 不允许稳定产线、市场或普通配方产出记忆源点。
- 不允许把矩阵精华退化成万能兑换货币。
- 不允许把黑雾矩阵映射成主线精华。

## 4. 主线阶段与黑雾边界

结论：主线阶段只由六色矩阵定义；黑雾保持战斗支线。

修改方向：

- 六色矩阵负责 FE 主线阶段。
- 原版科技树只作为矩阵阶段、原版进度和兼容事实来源，不作为 FE 自定义能力的玩家可见研究入口。
- 黑雾资源进入黑雾资源链、黑雾转化、黑雾成长报价、黑雾任务和黑雾成就。
- 黑雾内容按玩家实际接触时间穿插进任务和成就，而不是统一堆到最后。

禁止事项：

- 不允许黑雾矩阵进入主线矩阵阶段。
- 不允许黑雾矩阵进入矩阵萃取或产出精华。
- 不允许用黑雾基地等级推导科技阶段。
- 不允许黑雾奖励提供非战斗玩家无法替代的核心强度。

## 5. 通用分馏热路径

结论：保留统一热路径，所有 FE 分馏塔共享损毁、成功、直通、缓存、输出和成长回写语义。

修改方向：

- `BaseRecipe` 只定义通用结算语义。
- 配方子类只描述输出结构和少量特质。
- 热路径负责输送带、缓存、统计和成长回写。
- 必定成功或稳定兑换过程应进入数据中心、市场或专门兑换 UI。

禁止事项：

- 不允许在配方子类中复制完整热路径。
- 不允许把稳定兑换伪装成分馏配方。
- 不允许 UI 直接生产分馏产物。

## 6. 四类配方

结论：保留建筑培养、矿物复制、物品转化、精馏四类配方。

修改方向：

- 建筑培养：承担原胚修复和实体塔回退，保持简单、确定、可接入自动化。
- 矿物复制：承担基础资源补偿和新玩家最直观的分馏收益线。
- 物品转化：承担同类技术链条的结构化互转，后续重点审计链条清单。
- 精馏：承担矩阵到阶段坐标材料的萃取；精华重整只作为待验证辅助能力。

禁止事项：

- 建筑培养不再添加随机副产物来制造复杂度。
- 矿物复制不替代全部资源采集。
- 物品转化不做万能等价交换器。
- 精馏不接收黑雾矩阵，不使用独立阶段损毁表，不用“下一阶段使上一阶段贬值”表达成长。

## 7. 分馏塔、建筑成长与献祭

结论：保留四类塔、建筑成长和交互塔献祭。

修改方向：

- 四类塔与四类配方一一对应。
- 建筑成长用于逐步修复塔特质，不应开局一次性给完复杂能力。
- 交互塔献祭作为数据中心超量塔库存到对应塔运行增幅的辅助机制。
- 通用输出增强、产物输出增强和堆叠上限属于通用能力，不写成某个塔的独占特质。

禁止事项：

- 不允许新增万能塔绕过四类职责。
- 不允许因为文件大把同一个塔状态流拆到互不相干的目录。
- 不允许献祭读取历史累计上传量。

## 8. 时隧检索与确定性补差

结论：保留时隧检索、稳定锚定、检索偏向、回响和确定性补差。

修改方向：

- 时隧检索负责发现配方、塔原胚和旧文明修复材料。
- 稳定锚定负责降低长期随机挫败。
- 检索偏向只影响权重和折扣，不独立产出。
- 回响负责让全解锁后的重复命中变成轻量增益。
- 成长规划定位为确定性补差，不是商店。

禁止事项：

- 不允许把时隧检索写成二游抽卡。
- 不允许检索偏向独立产出物品。
- 不允许成长规划替代自动化产线。

## 9. 配方成长

结论：保留配方成长，作为“发现配方”之后的长期投入目标。

修改方向：

- 继续使用 `RecipeType + InputID` 作为基础定位。
- 如果后续允许同输入多路线，再引入更明确的路线键。
- 任务和成就统一使用覆盖率、比例、等级和回响口径。
- 成长 UI 从列表展示转向下一步推荐和缺口解释。

禁止事项：

- 不允许使用固定全部配方数量作为长期目标。
- 不允许 UI 直接改配方等级。
- 不允许把建筑成长和配方成长混成一个全局等级。

## 10. 统一堆叠与原版配方时间

结论：保留统一堆叠，并让原版配方时间随统一堆叠同步。

修改方向：

- 统一堆叠作为全局产线奖励。
- 原版配方时间只读取统一堆叠结果。
- 旧的逐配方时间升级概念应移除或隐藏为兼容层。

禁止事项：

- 不允许把原版配方时间重新做成逐配方升级。
- 不允许跨存档残留提供当前存档无法达到的唯一强度。

## 11. 数据中心与物流交互

结论：保留数据中心作为 FE 库存事实源；保留物流交互站作为自动化接入层。

修改方向：

- 数据中心保存实体库存和增产点。
- 数据中心通信入口由异常旧文明信号和启动套件建立，不再由主脑科技树研究解锁。
- 启动套件承接现有初始科技奖励的职责：提供通信方式、初始原胚和第一座交互塔，帮助玩家打通第一轮 FE 闭环。
- 手动数据中心操作和物流交互站共享同一套库存读写逻辑。
- 物流交互站负责把数据中心接回真实产线。
- 增产点池只作为物流交互站支撑能力。

禁止事项：

- 不允许 UI 凭空生成数据中心库存。
- 不允许用历史累计上传量替代当前实体库存。
- 不允许把启动套件扩写成超值礼包或后续阶段奖励的替代品。
- 不允许把增产点池写成第五条分馏路线。

## 12. 任务、成就、日志与引导

结论：保留任务、成就和日志，但继续校准顺序。

修改方向：

- 主线任务从“研究 FE 科技”改为“探测异常信号、前往指定地点、回收旧文明启动套件、接入数据中心、恢复协议”。
- 主线任务承担系统入口和阶段引导。
- 普通成就承担当前存档长期目标和轻量加成。
- 秘密成就承担跨存档发现、便利和展示。
- 日志用于校准成就顺序、检索节奏、成长报价和 UI 引导。

禁止事项：

- 不允许普通成就跨存档提供决定性强度。
- 不允许任务或成就使用固定全部配方数量作为目标。
- 不允许任务奖励替代稳定产线。

## 13. UI 主面板与页面

结论：UI 主面板保留，但具体页面需要逐页验证。

修改方向：

- UI 只做规划、展示和确认，不做生产事实源。
- 每个页面都必须证明长期使用价值。
- 只用一次、之后基本不用的页面应合并到任务、图鉴或弹窗说明中。
- 优先补“下一步做什么”“缺什么”“点哪里处理”的 QOL。

禁止事项：

- 不允许为了展示模块而保留页面。
- 不允许 UI 直接改配方等级、生成库存或绕过分馏热路径。
- 不允许用大段说明替代跳转和操作闭环。

待验证：

- 需要按当前主面板页面逐个读取入口和使用场景，再判断保留、合并或重写。

## 14. 全局红线

- `DESIGN.md` 只保留设计结论；公式、阈值和执行细节写入 `DESIGN_DETAILS.md`。
- `DESIGN_DETAILS.md` 只能细化本文，不能反向改变本文结论。
- UI 是规划、展示和确认层，不是生产层。
- 数据中心保存实体库存，不保存历史累计幻觉。
- 市场、成长规划、任务和成就是补差、引导或奖励层，不能替代产线。
- 后期允许净正收益，但必须来自明确输入、阶段门槛、成长投入和产线时间。
