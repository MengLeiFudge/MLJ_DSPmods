# Fractionate Everything 模块审计与方向设计

本文面向作者和 AI 维护者，不面向玩家宣传。

本文只回答“大方向”问题：模块为什么存在，解决什么问题，能否被其它机制替代，与其它模块如何交互，缺失时对玩家有什么影响，以及后续应该保留、合并、重写、降级、删除还是待验证。

本文不写公式、阈值、执行频率、具体数值、状态字段和代码级流程。这些内容写入 `DESIGN_DETAILS.md`。如果细则设计需要改变模块目的或审计结论，必须先修改本文。

## 1. 文档契约

### 1.1 两层设计文档

`DESIGN.md` 是上位约束文档：

- 记录模块必要性。
- 记录替代性判断。
- 记录玩家影响。
- 记录模块交互边界。
- 记录审计结论和后续修改方向。
- 记录禁止事项。

`DESIGN_DETAILS.md` 是机制细则文档：

- 记录公式、阈值、触发条件和执行频率。
- 记录状态字段、数据表、代码入口和 UI 操作细节。
- 按本文模块顺序细化执行规则。
- 只能细化本文，不能反向改变本文的模块目的。

实现规则：

- 代码实现以 `DESIGN_DETAILS.md` 的具体规则为准。
- `DESIGN_DETAILS.md` 的合法性由本文的方向约束决定。
- 若两份文档冲突，先修改本文的审计结论，再修改细则和代码。

### 1.2 审计结论格式

每个模块必须先写分析结果，再写审计结论。

结论类型：

- 保留：模块必要且边界成立，后续按当前方向继续细化。
- 合并：模块有价值，但应并入另一个模块。
- 重写：模块目标成立，但当前表现或实现方向不成立。
- 降级为辅助：模块不能作为主线，只能服务其它模块。
- 删除：模块价值不足或已有机制可替代。
- 待验证：缺少代码、数值、UI 或玩家行为证据，不能下最终结论。

审计结论必须能指导实际修改，不能只写“后续优化”。

## 2. 总体方向

### 2.1 分析结果

FE 的核心不是让玩家购买能力，而是让玩家在当前存档中逐步修复旧文明能力，并通过跨存档残留降低重复劳动。

玩家主循环：

1. 用原版矩阵打开旧文明入口。
2. 通过时隧检索发现配方、塔原胚和修复材料。
3. 用分馏塔把发现内容接入自动化产线。
4. 通过配方成长、建筑成长、统一堆叠和任务成就扩展能力。
5. 用数据中心与物流交互把 FE 库存接回真实工厂。

模块关系：

```text
旧文明入口
├── 当前存档修复
│   ├── 主线矩阵阶段
│   ├── 分馏配方成长
│   ├── 分馏塔建筑成长
│   ├── 统一堆叠与原版配方时间同步
│   └── 当前存档普通成就
├── 跨存档残留
│   ├── 旧文明残留收藏
│   ├── 秘密成就
│   └── 新存档提前访问与便利
├── 时隧检索
│   ├── 路线检索域
│   ├── 原胚检索域
│   ├── 稳定锚定
│   ├── 校准进度
│   └── 检索单位回响
├── 自动化分馏
│   ├── 通用分馏结算
│   ├── 建筑培养
│   ├── 矿物复制
│   ├── 物品转化
│   └── 精馏
├── 数据中心与物流交互
│   ├── 物品存储
│   ├── 建筑上传
│   ├── 正面交互
│   └── 增产点池
└── 玩家反馈
    ├── 主线任务
    ├── 普通成就
    ├── 秘密成就
    ├── 日志
    └── UI 页面
```

FE 的当前问题不是缺少机制，而是机制之间的必要性、替代关系和后续修改方向需要被逐模块写清楚。

### 2.2 审计结论

结论类型：保留核心系统，重写文档结构。

修改方向：

- 保留“矩阵阶段 -> 时隧检索 -> 自动化分馏 -> 成长/堆叠/成就 -> 数据中心反馈”的闭环。
- 本文负责模块方向和审计结论。
- `DESIGN_DETAILS.md` 负责具体执行细则。
- 后续 AI 修改代码前，必须先检查本文对应模块的审计结论。

禁止事项：

- 不允许把待验证模块当作稳定目标继续扩写。
- 不允许在本文塞入大量公式和参数，让方向层重新变成实现流水账。

## 3. 资源层级

### 3.1 分析结果

资源层级解决的问题是：FE 需要一套能连接分馏、检索、成长、成就和跨存档残留的价值系统。

资源分三层：

- 残片：底层成长材料，负责失败、重复、拆解和补差后的通用回收价值。
- 矩阵精华：阶段坐标和稳定材料，负责把原版矩阵转换为 FE 的旧文明修复语言。
- 记忆源点：最高层非产线记忆锚点，负责一次性高层奖励、补偿和跨存档便利。

必要性判断：

- 残片有必要保留。没有残片，失败和重复检索缺少回收反馈，成长补差会变硬。
- 矩阵精华有必要保留。没有精华，精馏塔会变成孤立兑换器，时隧检索缺少稳定坐标。
- 记忆源点有必要保留，但必须保持非产线属性。没有它，跨存档残留和一次性高层奖励缺少上位锚点。

替代性判断：

- 原版矩阵不能替代矩阵精华。矩阵是原版科技产物，精华是 FE 旧文明坐标材料。
- 残片不能替代记忆源点。残片是可回收底层材料，记忆源点必须表达稀缺锚点。
- 市场板不能替代资源层级。市场只能做有限补差，不能成为资源价值事实源。

玩家影响：

- 三层资源让玩家能区分“可回收材料”“阶段坐标”“稀缺锚点”。
- 如果所有资源都压成一种货币，FE 会丢失阶段感和模块分工。

### 3.2 审计结论

结论类型：保留。

修改方向：

- 保留残片、矩阵精华、记忆源点三层资源。
- 删除或隐藏目标设计中其它源点概念；旧 ID 只能作为存档兼容占位。
- 残片来源以检索回收、拆票、任务和补偿为主。
- 矩阵精华必须继续服务时隧检索和精馏，不允许退化成万能兑换货币。

禁止事项：

- 不允许稳定产线、市场、普通配方产出记忆源点。
- 不允许把黑雾矩阵映射成主线精华。
- 不允许让市场板成为资源层级的核心事实源。

## 4. 主线阶段与黑雾边界

### 4.1 分析结果

主线阶段解决的问题是：FE 需要跟随原版科技进度逐步开放旧文明修复能力。黑雾系统虽然是重要支线，但黑雾矩阵不属于六色矩阵主链，不能反向污染主线阶段。

必要性判断：

- 主线阶段有必要保留。它控制玩家接触 FE 能力的节奏，避免开局信息过载。
- 黑雾边界有必要明确。黑雾是战斗支线，不是主线矩阵阶段的一部分。

替代性判断：

- 不能用黑雾基地等级替代矩阵阶段。基地等级表达战斗进度，不表达科技链阶段。
- 不能用“玩家获得了黑雾矩阵”推导主线阶段。黑雾矩阵的来源和用途都不等同于六色矩阵。

玩家影响：

- 没有阶段边界，检索、成长和 UI 解锁会失去节奏。
- 黑雾若混入主线矩阵阶段，会让非战斗玩家的主线体验被战斗系统绑架。

### 4.2 审计结论

结论类型：保留。

修改方向：

- 主线阶段继续只由六色矩阵定义。
- 黑雾矩阵不进入矩阵萃取，不产出精华，不映射到信息、引力或宇宙阶段。
- 黑雾内容进入黑雾任务、黑雾成长报价和黑雾资源链。

禁止事项：

- 不允许用黑雾基地等级推导主线矩阵阶段。
- 不允许把黑雾矩阵写成主线检索燃料。
- 不允许用黑雾支线奖励替代当前存档主线修复奖励。

## 5. 通用分馏热路径

### 5.1 分析结果

通用分馏热路径解决的问题是：所有 FE 分馏塔必须共享同一套损毁、成功、直通、缓存、输出和成长回写规则。否则四类塔会变成四套不可比较的机制，玩家也无法建立稳定预期。

必要性判断：

- 通用热路径是 FE 自动化系统的底座，必须保留。
- 它解决玩家对所有塔的统一认知：输入可能损毁、成功产出或直通，而不是每个塔单独学一套规则。

替代性判断：

- 不能用 UI 按钮或数据中心兑换替代热路径。那会把自动化玩法降级成菜单操作。
- 不能让每种配方自己写完整结算。那会制造概率、缓存、增产、成长回写的重复分叉。

玩家影响：

- 没有统一热路径，玩家无法通过一座塔的经验理解其它塔。
- 热路径不稳定会直接导致堵线、吞物、随机收益解释不清和性能问题。

实现方向：

- 配方子类只描述输出结构和少量特质，不重写底层输送、缓存和成长回写。
- 跨存档秘密成就只能提供便利、提示或提前访问，不直接改变新存档损毁率。
- 塔窗口必须明确区分直通输出和输入保留。

### 5.2 审计结论

结论类型：保留。

修改方向：

- 继续把损毁、成功、直通、缓存和成长回写集中在分馏热路径。
- 四类配方不得绕开 `BaseRecipe` 的基本语义。
- 需要必定成功的过程应转移到数据中心、市场或专门兑换 UI。
- 热路径相关文件可以拆分，但必须按职责拆分。

禁止事项：

- 不允许在配方子类中复制完整热路径。
- 不允许把稳定兑换伪装成分馏配方。
- 不允许让 UI 直接生产分馏产物。

## 6. 四类配方

四类配方是 FE 自动化内容的主体：建筑培养、矿物复制、物品转化、精馏。它们都服从通用热路径，但各自解决不同问题。

### 6.1 建筑培养

#### 分析结果

建筑培养解决的问题是：旧文明塔从哪里来，以及实体塔如何回退成原胚。没有建筑培养，原胚检索和塔成长就只能停留在奖励物品层，无法进入自动化系统。

必要性判断：

- 建筑培养有必要保留。它把检索获得的原胚转化为可建造实体塔，并允许玩家回收布局。
- 它不可被普通制作配方替代。普通制作只表达制造，不表达旧文明设备修复和反向回退。

玩家影响：

- 没有建筑培养，原胚检索只会变成开箱奖励，和分馏塔自动化脱节。
- 没有实体塔回退，玩家调整产线成本过高，也不利于数据中心和任务系统读取塔库存。

#### 审计结论

结论类型：保留。

修改方向：

- 保留原胚到实体塔、实体塔到原胚的双向培养。
- 继续收敛到四类实际塔原胚，不把定向原胚作为常规核心对象。
- 建筑培养 UI 应强调修复、回退和库存管理。

禁止事项：

- 不允许再给建筑培养添加随机副产物来制造复杂度。
- 不允许把建筑培养降级为普通手搓配方。

### 6.2 矿物复制

#### 分析结果

矿物复制解决的问题是：资源贫瘠星区和长线产线需要资源补偿，同时玩家希望某些原矿、矿物和掉落能进入 FE 成长系统。

必要性判断：

- 矿物复制有必要保留。它是最容易理解的自动化收益线，也是新玩家理解“成功分馏”的入口。
- 原版矿机、增产剂和星际物流只能提高获取效率，不能替代“低概率复制 + 成长”的旧文明机制。

玩家影响：

- 没有矿物复制，FE 缺少最直观的资源向收益，前期很难让玩家建立正反馈。
- 如果矿物复制过强，会让原版矿脉和物流规划失去意义。

#### 审计结论

结论类型：保留。

修改方向：

- 保留矿物复制作为基础自动化收益线。
- 副产物只保留强资源关系，避免泛化。
- 成长重点放在输入保留、产物翻倍、产物增产点数和效率，而不是增加新随机表。

禁止事项：

- 不允许让矿物复制替代所有资源采集。
- 不允许把普通制造材料按价值相近塞进矿物复制。

### 6.3 物品转化

#### 分析结果

物品转化解决的问题是：同类功能链条中的物品需要可成长的结构化互转，例如物流、建筑、燃料、军工和黑雾资源链。它让 FE 可以表达“旧文明正在重组同一技术链条”，而不是做市场等价交换。

必要性判断：

- 物品转化有必要保留。它是 FE 中最能承载“简单机制产生复杂可能性”的模块。
- 它不能被市场替代。市场表达补差和交易，转化塔表达自动化链条变形。

玩家影响：

- 没有转化，FE 会只剩复制和精馏，缺少中后期针对技术链的产线玩法。
- 没有单路锁定，转化塔后期难以接入稳定蓝图，会成为随机垃圾产物源。

#### 审计结论

结论类型：保留，但继续收紧边界。

修改方向：

- 物品转化只允许相关链条转化。
- 单路锁定必须作为后期稳定产线能力保留。
- 后续重点应审计链条清单，而不是扩展转化系统本身。

禁止事项：

- 不允许把转化塔做成万能等价交换器。
- 不允许用“价值相近”作为普通中间件互转理由。
- 不允许把单路锁定做成 UI 伪过滤；它必须影响热路径输出。

### 6.4 精馏

#### 分析结果

精馏解决的问题是：矩阵需要被转换成旧文明阶段坐标和检索稳定材料。它不是市场兑换，也不是万能货币压缩器。

必要性判断：

- 精馏有必要保留，因为它把原版矩阵、FE 检索和成长催化连接起来。
- 但精馏不能无限扩张。它的核心意义是阶段坐标，不是另一个市场。

替代性判断：

- 直接消耗矩阵不能替代精华。直接消耗会让精馏塔失去存在价值。
- 市场兑换不能替代精馏。市场没有自动化热路径和阶段坐标语义。

玩家影响：

- 没有精馏，时隧检索缺少稳定材料，矩阵阶段也无法转化为 FE 自己的成长语言。
- 如果精馏过度复杂，玩家会把它理解成另一套货币交易，反而削弱分馏系统整体清晰度。

#### 审计结论

结论类型：保留，但重整部分待验证。

修改方向：

- 保留矩阵萃取。
- 精华重整如果继续存在，应降级为精馏辅助能力，不能抢走矩阵萃取的核心地位。
- 后续应审计重整表是否真的解决玩家问题；如果只是货币换算，应迁到数据中心或删除。

禁止事项：

- 不允许黑雾矩阵进入精馏。
- 不允许精馏使用独立阶段损毁表。
- 不允许用“下一阶段使上一阶段贬值”表达成长。

## 7. 分馏塔、建筑成长与献祭

### 7.1 分析结果

分馏塔与建筑成长解决的问题是：同一套分馏热路径需要不同设备承担不同能力，玩家也需要长期升级目标。塔不是配方 UI 的皮肤，而是自动化系统里的实体能力载体。

四类塔方向：

- 交互塔：建筑培养、实体塔回退、数据中心上传、献祭。
- 矿物复制塔：资源复制、副产物、产物增产点数。
- 转化塔：同链条转化、单路锁定、输入保留。
- 精馏塔：矩阵萃取、精华重整、精华催化。

献祭方向：

- 献祭把数据中心中超量的分馏塔库存转化为对应塔运行增幅。
- 它让长期重复获得的塔有回收价值，并把数据中心库存和自动化热路径连接起来。
- 献祭不能替代建筑成长，也不能消耗历史累计上传量，只能消耗当前实体库存。

必要性判断：

- 四类塔有必要保留，因为它们把四类配方的职责落到实体建筑上。
- 建筑成长有必要保留，因为它给自动化产线提供长期目标，而不是只靠 UI 点数升级。
- 献祭有必要保留为辅助机制，因为它消化重复塔库存，并给长期运行提供短周期反馈。

替代性判断：

- 不能用一个万能塔替代四类塔。万能塔会压扁配方差异，UI 和产线都失去可读性。
- 不能用纯科技升级替代建筑成长。科技升级是全局阶段，建筑成长是产线投入反馈。
- 不能用市场回收替代献祭。市场回收只处理价值，献祭连接的是数据中心库存和塔运行增幅。

### 7.2 审计结论

结论类型：保留。

修改方向：

- 保留四类塔与四类配方一一对应的结构。
- 继续统一三口模型，并把塔型特质作为增量能力。
- 建筑成长应逐步修复特质，而不是开局一次性给完复杂能力。
- 献祭作为交互塔和数据中心之间的辅助增幅机制保留。

禁止事项：

- 不允许新增万能塔来绕过四类职责。
- 不允许因为文件大把同一个塔状态流拆到互不相干的目录。
- 不允许把通用输出增强误写为某个塔的独占特质。
- 不允许献祭读取历史累计上传量。

## 8. 时隧检索与确定性补差

### 8.1 分析结果

时隧检索解决的问题是：配方、塔原胚和修复材料不能全部靠科技树线性发放，否则 FE 会缺少探索和长期补差空间。检索把随机性解释为旧文明时间隧道中的技术片段搜索。

检索模块包括：

- 检索域：限定可发现内容范围。
- 稳定锚定：降低长期随机挫败。
- 信号完整度：表达结果质量。
- 校准进度：承接重复和失败后的确定性补差。
- 检索偏向：改变权重与折扣，不独立产出。
- 回响：让全解锁后的重复命中变成轻量增益。

必要性判断：

- 时隧检索有必要保留。它承担配方开线、原胚来源和重复命中的回响收益。
- 确定性补差有必要保留。纯随机会让玩家在后期补齐目标时成本不可控。

替代性判断：

- 科技树不能替代检索。科技树适合阶段门槛，不适合大量可发现配方和塔原胚。
- 市场不能替代确定性补差。市场是资源供应，补差是检索失败和重复后的收束机制。

### 8.2 审计结论

结论类型：保留，但 UI 语义继续重写。

修改方向：

- 保留时隧检索、稳定锚定、检索偏向和回响。
- 成长规划定位为确定性补差，不是商店。
- 所有玩家可见抽卡、卡池、保底、稀有度、成长积分语义继续替换为检索语言。

禁止事项：

- 不允许把检索写成二游抽卡。
- 不允许让检索偏向独立产出物品。
- 不允许让成长规划替代自动化产线。

## 9. 配方成长

### 9.1 分析结果

配方成长解决的问题是：同一个配方需要从“发现”走向“可长期投入”，否则检索开线后缺少后续目标。成长状态也让任务、成就、UI 和检索回响能读取同一套事实。

必要性判断：

- 配方成长有必要保留。它把一次性解锁转化为长期投入目标。
- 它不能被建筑成长替代。建筑成长是设备能力，配方成长是工艺熟练度。

玩家影响：

- 没有配方成长，检索开线后收益会过快结束。
- 如果成长口径用固定总数，兼容模组变化会让任务难度和可完成性失控。

### 9.2 审计结论

结论类型：保留。

修改方向：

- 保留 `RecipeType + InputID` 作为基础键；若后续允许同输入多路线，再引入更明确的路线键。
- 任务和成就统一使用覆盖率、比例、等级和回响口径。
- 成长 UI 应从“列表展示”转向“下一步推荐和缺口解释”。

禁止事项：

- 不允许使用固定全部配方数量作为长期目标。
- 不允许让 UI 直接改配方等级。
- 不允许把建筑成长和配方成长混成一个全局等级。

## 10. 统一堆叠与原版配方时间

### 10.1 分析结果

统一堆叠解决的问题是：FE 后期吞吐大幅提升后，原版蓝图如果仍按低堆叠和原版配方时间运行，会被吞吐不匹配拖垮。原版配方时间不应再作为逐配方升级项目，而应随统一堆叠自动同步。

必要性判断：

- 统一堆叠有必要保留。它是旧文明核心修复最直接的全局产线奖励。
- 原版配方时间同步有必要保留。否则堆叠提升会破坏原版产线配比。

替代性判断：

- 逐配方时间升级不能替代统一同步。逐配方升级操作成本高，也不利于旧蓝图继续工作。
- 只提升分馏塔不够。FE 的后期吞吐会影响整个工厂，不是单个塔的问题。

玩家影响：

- 没有统一堆叠，后期物流和产线吞吐会成为无趣瓶颈。
- 没有时间同步，玩家需要大规模重调原版蓝图。

### 10.2 审计结论

结论类型：保留。

修改方向：

- 保留统一堆叠作为全局产线奖励。
- 原版配方时间继续由统一堆叠同步。
- 移除或隐藏逐配方时间升级概念；旧代码名只能作为兼容层。

禁止事项：

- 不允许把原版配方时间重新做成逐配方升级。
- 不允许让跨存档残留提供当前存档无法达到的唯一强度。

## 11. 数据中心与物流交互

### 11.1 分析结果

数据中心解决的问题是：FE 需要一个稳定库存事实源，连接分馏塔、检索、任务、成就、物流交互和 UI。物流交互站解决的问题是：数据中心不能只停留在菜单库存，必须能接入真实产线。

必要性判断：

- 数据中心有必要保留。没有它，FE 的资源和建筑库存会散落在玩家背包、塔缓存、物流站和 UI 临时状态中。
- 物流交互有必要保留。没有它，数据中心会变成手动仓库，无法服务自动化。

替代性判断：

- 玩家背包不能替代数据中心。背包是个人瞬时库存，不是 FE 系统事实源。
- 物流站不能替代数据中心。物流站是原版物流节点，不理解 FE 检索、成长和任务事实。

玩家影响：

- 没有数据中心，玩家很难理解 FE 资源在哪里、任务从哪里读取。
- 没有物流交互，数据中心会增加手动搬运负担。

### 11.2 审计结论

结论类型：保留。

修改方向：

- 保留数据中心作为 FE 库存事实源。
- 保留物流交互站作为自动化接入层。
- 手动数据中心操作和物流交互站应共享同一套库存读写逻辑。
- 增产点池属于物流交互站支撑能力，不是第五条分馏主线。

禁止事项：

- 不允许 UI 凭空生成数据中心库存。
- 不允许用历史累计上传量替代当前实体库存。
- 不允许把增产点池写成第五条分馏路线。

## 12. 任务、成就、日志与引导

### 12.1 分析结果

任务和成就解决的问题是：FE 系统复杂，玩家需要被引导逐步接触核心模块，同时作者需要知道玩家真实完成顺序来调整节奏。日志是后续平衡和 UI 调整的证据来源。

必要性判断：

- 任务有必要保留。它承担新系统发现和阶段引导。
- 成就有必要保留。它承担长期目标和轻量加成。
- 日志有必要保留。没有日志，成就顺序和难度调整只能靠猜。

替代性判断：

- 教程文本不能替代任务。教程解释“是什么”，任务告诉玩家“下一步做什么”。
- 成就不能替代主线任务。成就更适合长期或挑战，主线适合当前阶段引导。

玩家影响：

- 没有引导，FE 的入口、检索、成长、数据中心和物流交互会过于分散。
- 成就如果给决定性强度，会让玩家被迫刷目标而不是自然推进。

### 12.2 审计结论

结论类型：保留，但需要继续校准顺序。

修改方向：

- 主线任务承担系统入口和阶段引导。
- 普通成就承担当前存档长期目标和轻量加成。
- 秘密成就承担跨存档发现、便利和展示。
- 通过日志持续校准任务和成就顺序。

禁止事项：

- 不允许普通成就跨存档提供决定性强度。
- 不允许任务/成就用固定全部配方数量作为目标。
- 不允许任务奖励替代稳定产线。

## 13. UI 主面板与页面

### 13.1 分析结果

UI 页面解决的问题是：FE 模块多，玩家需要理解当前资源、检索、配方、建筑、任务和数据中心状态。但页面本身不是目标，只有能降低理解成本、支持长期操作或提供必要反馈的页面才应该存在。

必要性判断：

- UI 有必要保留，但页面数量必须受审计约束。
- 只使用一次、之后没有长期价值的页面应合并到任务、图鉴或弹窗说明中。

替代性判断：

- 塔窗口不能替代主面板。塔窗口服务当前建筑，主面板服务全局规划。
- 主面板不能替代塔窗口。主面板不能完成所有实时产线状态反馈。

玩家影响：

- UI 不清晰会让玩家不知道 FE 下一步该做什么。
- 页面过多会让玩家把 FE 理解成菜单堆叠，而不是自动化系统。

### 13.2 审计结论

结论类型：待验证。

判断理由：

- UI 页面的必要性不能只靠设计推导，需要结合当前页面使用频率、重复入口和玩家卡点。
- 当前可先保留主页面域，但后续需要逐页审计是否长期有用。

修改方向：

- 后续逐页审计：页面是否必要、是否长期使用、是否可合并、缺哪些 QOL。
- 优先改“看不懂下一步”和“只用一次就废弃”的页面。
- UI 页面只做规划、展示和确认，不做生产事实源。

禁止事项：

- 不允许为了展示模块而保留页面。
- 不允许 UI 直接改配方等级、生成库存或绕过分馏热路径。
- 不允许把引导写成大段说明而没有跳转和操作闭环。

缺失证据：

- 需要按当前主面板页面逐个读取实现和入口，再判断哪些页面应保留、合并或重写。

## 14. 黑雾支线

### 14.1 分析结果

黑雾支线解决的问题是：深空来敌相关资源和战斗进度需要接入 FE，但不能支配主线矩阵阶段。黑雾应该提供额外资源链、成长报价、任务和成就，而不是变成第七种主线矩阵。

必要性判断：

- 黑雾支线有必要保留。它让战斗系统玩家获得额外目标，也能把黑雾掉落纳入 FE 转化链。
- 黑雾支线必须保持支线属性。主线 FE 不应强迫玩家通过战斗获得基础能力。

替代性判断：

- 主线矩阵阶段不能替代黑雾支线，因为黑雾资源来自不同玩法。
- 黑雾支线不能替代主线矩阵阶段，因为它不表达原版科技链。

玩家影响：

- 没有黑雾支线，战斗玩家获得的黑雾资源缺少 FE 内用途。
- 黑雾支线如果过强，会让非战斗路线被迫跟进。

### 14.2 审计结论

结论类型：保留为支线。

修改方向：

- 黑雾继续作为战斗支线接入 FE。
- 黑雾资源链只影响黑雾相关转化、补差、任务和成就。
- 黑雾 UI 和任务按实际接触时间穿插，而不是放到最后统一处理。

禁止事项：

- 不允许黑雾矩阵成为主线矩阵阶段。
- 不允许黑雾奖励提供非战斗玩家无法替代的核心强度。
- 不允许把黑雾基地等级当作科技阶段。

## 15. 全局红线

- 目标设计中只有记忆源点这一种源点。
- 黑雾矩阵不进入主线矩阵阶段，不进入矩阵萃取，不产出精华。
- 建筑培养目标产物为对应实体塔或对应塔原胚。
- 原版配方时间随堆叠统一同步，不再独立逐配方升级。
- 配方任务和成就使用比例、覆盖率、等级和回响口径，不使用固定总数。
- 普通成就是当前存档任务列表；秘密成就才跨存档。
- UI 是规划、展示和确认层，不是生产层。
- 数据中心保存实体库存，不保存历史累计幻觉。
- 市场、成长规划、任务和成就是补差、引导或奖励层，不能替代产线。
- 后期允许净正收益，但必须来自明确输入、阶段门槛、成长投入和产线时间。
