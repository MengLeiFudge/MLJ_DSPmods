# Fractionate Everything 游戏设计规格

本文细化 `GAME_DESIGN.md`，记录当前数值、公式、状态、结算顺序与操作合同。两份文档章节一一对应。

## 1. 设计目标

### 1.1 单位与结算

- FE顶层保存版本固定为10；业务字段和数据块增删沿标签化结构处理，不升级顶层版本。
- 玩家中文名为源点（Memory）、残片（Frag）；内部稳定身份保留原名。
- 游戏时间每秒60 tick，每分钟3600 tick。
- 数量单位为件；亚空间容量为物品基准件数乘永久容量倍率；货物缓存的堆数乘全局集装数；能量单位为J。
- 批量概率使用 `floor(expected + U)`，U为[0,1)均匀随机数，不等同于逐件独立伯努利采样。

### 1.2 状态归属

| 领域 | 真源 |
| --- | --- |
| 配方与唯一解析样本 | RecipeManager / WorldviewRecipe |
| 已发现内容、共享进度、阶段恢复、分钟献祭 | ResearchManager / ResearchProgression |
| 地点、奖励记录、主线与终极任务 | ExplorationManager |
| 科技定义与效果投影 | GrowthTechnologyManager；完成状态为GameHistoryData |
| 数量、增产点与容量 | DataCenterInventory；SubspaceExpansion拥有扩容供料及永久倍率 |
| 基础塔与高级塔 | FractionatorRuntime / AdvancedFractionatorRuntime |

Nebula传输上述状态，不复制一套结算规则。UI只读快照并调用显式命令。

## 2. 世界观与开局

### 2.1 开局与阶段节点

开局待母星工厂及黑雾基地数据就绪后建立首遗物。候选点位于出生点所在半球，距出生点地表弧长100～160m，距每座现存黑雾基地的地表弧长至少200m；每次有界搜索，找不到安全点则等待下次搜索，不退回对跖点或放宽安全圈。岩石星关键点认领半径30m；回收自动建立亚空间通信；主面板百科此前即可打开，不经额外网络科技。

首遗物奖励基础矿物塔4座、基础解析塔2座，解锁两种塔的制造配方；普通配方由矩阵科技开放，不再发放这些配方的解析线索。不开局解锁矿物复制，不发原胚或高级塔。机甲移动、物流与集装科技由玩家自行研究，首遗物不授予这些科技或额外物流补给。

| 主线序号 | 阶段与地区 | 必要条件/关键物资 |
| --- | --- | --- |
| 1～3 | 开局母星 | 第3点要求至少恢复一份研究内容 |
| 4～6 | 电磁矩阵、母星 | 第4点要求电磁矩阵实际首次生产，给予交互塔2、原胚60、Memory30 |
| 7～9 | 能量矩阵、母星 | 每点给予Memory12 |
| 10～12 | 结构矩阵、出生星系其他岩石星 | 排除母星；没有其他岩石星时才回退 |
| 13～15 | 信息矩阵 | thrusterLevel≥3时优先最近另一星系，否则留在出生星系；文案按实际是否跨星系选择 |
| 16～18 | 引力矩阵 | 同13～15 |

节点顺序完成并持久化。第5、8点继续说明矿物塔及转化塔用途，培育资格由矩阵科技提供。实际首次电磁矩阵生产通过原版 `MST_ItemFirstProduction` 的物品里程碑判断，不用科技解锁替代。

解析首次涉及某高级塔型的高级配方时，恢复该型原型1座，按塔型去重；常规量产依靠培育。

### 2.2 通关档案

本地 `Progression/CompletedWorlds` 保存完成过丰碑终局的世界身份，通关次数等于去重身份数。身份由原版星图seedKey64与世界创建时间Ticks组成，另存和重复读档仍视为同一世界。旧HasPlayedFractionation3配置及存档StackProgressionMode块不再使用，不折算为通关次数。

丰碑终局由主机确认后记录一次；沙盒模式、历史沙盒创建标记、启用过沙盒工具或使用过原版一键解锁，都会使Research的 `CompletionDisqualified` 永久为true，读档不能恢复资格。当前格式缺少资格记录时禁止授予；从2.2导入的世界不授予通关。已记录的独立世界不会重复计数。

## 3. 五塔工业

### 3.1 原型与基础塔

| 塔型 | Item | Model | 配方类型 |
| --- | ---: | ---: | --- |
| 基础矿物塔 | 8123 | 653 | BasicMineral=3 |
| 基础解析塔 | 8122 | 652 | BasicAnalysis=2 |
| 高级矿物塔 | 8125 | 655 | AdvancedMineral=5 |
| 高级交互塔 | 8121 | 651 | AdvancedInteraction=1 |
| 高级转化塔 | 8124 | 654 | AdvancedConversion=4 |

基础塔制造配方为1063、1064。基础矿物塔使用石材10、铁块20、电路板5；基础解析塔使用铁块20、棱镜10、电路板5，不消耗原版分馏塔。星环启用时，两种配方的电路板1301均替换为电路控制元件1302，数量不变；该元件直接用于电气矩阵，避免基础塔依赖二级电路的石油化工链。创世与原版保留电路板，其余材料、数量、制造时间和首遗物解锁条件不变。

基础塔单输入自动识别，输入准入阈值为 `20×全局堆叠` 件，流动输出与每种产物的阈值为 `5×全局堆叠` 件。当前量低于阈值时接收完整货物或结算完整本帧批次，允许本次越界；达到阈值才暂停后续接收或反应。每秒处理速率为 `min(1, 实际货物堆数/10)×MaxBeltSpeed×平均每堆件数×供电比例`，速度公式与输入件数策略保持。运行、窗口及简洁提示共用此值；30堆/秒带速、无堆叠、满供电时为1800次/分钟。基础矿物候选由原版自然资源目录建立，排除珍奇矿物、黑雾特殊材料、无效价值物品。已解析配方为同物1→同物2，成功率5%，失败原样流出，无通用损毁率。

无增幅的基础成功率、基础损毁率各不超过20%；常规处理宜低于10%，纯消耗入口可为5%～10%。已定义增益仍按对应公式叠加。全部未处理且未损毁的反应物保留增产点侧流，每种塔至少有一个配方正面输出实物。高级塔食物接收与消化不属于反应；丰碑结晶确定性解析按7.4例外处理。

基础解析入口包含研究样本、Memory、Frag、高级塔、电路板、丰碑结晶及六种主线矩阵。样本规则见4.1，电路板制样和概率消耗规则见4.4；矩阵被选中后优先转入全局扩容供料，未被选中部分原样侧流，通信未恢复时全部流回。没有可研究内容且无合格特殊入口时，不判定损毁。解析实物产物按物品分别使用 `5×全局堆叠` 件阈值，当前量均低于阈值时完整结算本批，不预留最坏产量。任一产物达到阈值后停止研究，输入原样侧流；流出达到阈值后暂停相应处理，继续排出既有产物及流出物。首次应用新产物目录时保留已有缓存，不因读档目录变化丢物。

正面输入、两个侧面未接入时，基础塔执行亚空间上传，不额外耗能；整堆在同一库存锁内取货并按容量入库，超额部分按统一价值登记不可逆扩容积累。未知估值不能折算，剩余实体容量不足整堆时不取货。

### 3.2 高级塔缓存与反应

按 `(planetId, fractionatorId)` 保存选定稳定配方整数ID、逐物品输入件数/货物堆数/增产点、食物及增产点、产物、失败流出及增产点、消化物ID/剩余能量/单件增产点和输出游标。各物品独立准入：主料与辅料输入 `40×全局堆叠` 件；消耗概率低于10%的催化剂阈值为max(5,一轮需求)件，流动输出与每种产物 `5×全局堆叠` 件。当前量低于阈值可接收完整货物或执行完整本批，允许结果越界；产物阈值不随单成功轮产量变化，运行、原版镜像与窗口读取相同值。备用食物单独保存一类矩阵，硬容量等于当前全局堆叠层数，消化槽另存一件。输入按件数准入，InputCargo用于全塔共享货物速率额度的分摊与真实堆叠换算。传送带输入货物堆数按进入输入槽的件数/整堆件数增加，处理或手动取出时按件数比例扣减，保留真实平均堆叠。人工补料没有带上货物元数据，按当前全局堆叠折算新增货物数。

输入顺序：在同一带路径锁中窥看整堆；普通营养按当前全局堆叠层数对应的硬容量填备用。矩阵同时属于当前配方输入时，仅在断粮且备用空时留一件点燃，其余优先进入反应输入；已在燃烧时不持续截留该反应物填满食物槽。非反应营养必须与消化物及备用同种。产物堵塞时反应输入侧流，流出达到阈值则完整货物留在带上。其他情况下剩余货物完整进入低于阈值的输入或流出，不能只取食物而遗失余量。旧配方输入、堵塞反应物与异种旧食物逐批排出，目的槽满时保留。空消化槽的多种旧备用按营养值选择，同值按ID稳定排序。

对每项主消耗输入i，令件数为n_i、真实货物堆数为c_i、配方每轮需求为q_i、已推进但尚未结算的件数为a_i。实物始终保存在Inputs，a_i包含小数且不超过n_i；辅料与催化剂不累计主料进度，只要求缓存至少q_i件。

全塔货物速率上限C为侧面输入带的belt.speed×6之和，并封顶MaxBeltSpeed；无侧面输入带时使用MaxBeltSpeed，允许手工库存继续处理。正常主料速度倍率v_i=foodSpeed×durabilityEfficiency；旧输入及产物堵塞时待排空输入v_i=1，正常辅料与催化剂v_i=0。仅对有实物且对应流出低于阈值的输入求D=Σ(c_i×v_i)，共享倍率s=min(1,C/D)，D为0时s=0。各项f_i=c_i×v_i×s×(n_i/c_i)=n_i×v_i×s件/秒，每游戏刻独立推进a_i=min(n_i,a_i+f_i/60)。空输入及流出堵塞项不推进、不占额度，其余物品继续流动。消化槽有能量时耐久效率为1，否则为当前耐久比例。相同货物数下平均堆叠翻倍，件数速率翻倍；多项主料不能各自获得一条满带额度，积压较多项按真实货物需求获得更多额度。食物不参与主料配对。

主料、辅料、催化剂最低持有量齐备且全部主料流出与产物低于阈值时，本帧配对轮数 `k = min_i(floor(a_i/q_i), floor(n_i/q_i))`。按k轮统一结算成功、失败回流、辅料消耗、产物与营养；每项主料同时扣实物和对应进度k×q_i。物品数先限制为真实库存再转整数，高倍率不会累计无实物支持的进度，也不使用原版整机progress作为业务真源。

配对后，逐主料将 `max(0,floor(a_i)−q_i)` 件未配对物原样侧流，保留增产点；对应流出达到阈值时暂不搬运。旧输入及产物堵塞时待排空输入使用同一共享额度推进，按floor(a_i)排出，不保留配对储备；输入进度导入只按实际库存限制，不删除旧输入的合法小数进度。保留的一轮配对储备与小数进度用于吸收零散供料和到货相位差，避免未凑齐就全部流走。缺其他主料或催化剂不阻止已有主料循环；不强制各槽库存相等。每次取物同时扣对应推进件数并限制到剩余实物，手动取物不计运行流量。换配方清除推进与采样，共同输入实物保留。

流出及产物仍按本批开始前数量准入，允许完整本批跨阈值，不预留最大成功数。任一产物达到阈值后停止反应，现有及新到反应物按既有直通路径侧流；流出低于阈值才可继续转入，产物降到阈值以下恢复。催化剂、食物或无关物的独立流出积压不占其他物品的空间。

主机每30游戏刻公布一次实际流量：每种主料为该窗口从输入移出的配对件数、未配对回流及堵塞排空件数之和×2件/秒；配对速率为窗口实际k之和×2轮/秒。手动取出、新到物直接旁路与旧配方无关物不计入。槽位速率不是输入传送带接收量；辅料、催化剂、产物按配对速率与成功规则估算。采样计数不持久化，切档或换配方重新采样，满半秒无经过时公布0。

`p = min(1, 0.08 × (1+B))`；B的上限为0.75，最终成功率最高14%。

`success = min(k, floor(k×p+U))`

初抽成功数后、扣任何主料之前，对每项非主料计算每成功轮期望消耗q_i×p_i（特质后的实际概率），将成功数限制为min(原成功数,floor(库存/(q_i×p_i)))；p_i=0只保留最低持有量检查，不除零。余轮全部作为失败回流。随后主料先扣k轮、失败部分保留增产点回流，非主料按double期望 `floor(success×q_i×p_i+U)` 实扣，产物与营养统一使用最终成功数。库存为整数时无需预扣1；不通过限制尝试轮数压低低成功率配方吞吐。B见4.3。

正面belt0仅在isOutput0时输出Products；侧面belt1/belt2由isOutput1/2决定进出，只输出FlowOutputs。切换配方时共同输入保留，旧输入逐批侧流，旧产物保留并从正面优先排空。两个侧面流出口共用货物发送额度，每刻增加C/60，最多积攒一堆；成功发出一堆才扣1，失败不扣，换配方或重新载入清零且不持久化。包含旧料、直通和失败回流在内，整机持续流出最高为C×当前堆叠件/秒，整堆离散发送可有单堆相位差；瞬时流出可包含之前的缓存，不要求与同一刻到货数量相等。配方产物不占此回流额度。流动物按配方输入顺序轮转，多产物按库存加权轮转；无关物与旧产物优先排空。主料、催化剂足够一轮且输出当前量低于阈值时等待全局满堆；缺料或达到阈值时释放尾料，停机期间继续排出既有流动物与产物。

### 3.3 配方目录

高级配方在最终LDB加载后，由ItemAvailability求合法来源闭包：主题中有产量的矿脉、稀有追加、海洋、气巨及植被采集，特殊恒星矿脉，黑雾掉落，FE真实奖励/献祭与外部显式RegisterExternalSource声明作为起点；按全部输入可达展开普通及FE高级配方，发电设施产物还要求设施本身可达。不用GridIndex、maincraft、当前解锁状态或资源名称代替来源判断，不接受没有独立入口的循环。任一输入、研究样本不可达或产物原型缺失时，删除整张运行配方并重建全部索引，隐藏高级展示原型；随后才建立研究与解析目录。

### 3.4 供养与耐久

食物资格为已加载Type==Matrix或黑雾矩阵5201，且具有有限正估值。最终物品价值计算后建立MatrixNutrition目录，不按连续ID推断档位；未知估值记录明确诊断并不接收。以电磁矩阵价值V_b为基准，任一食物价值V对应基础能量 `N=5.25×sqrt(V/V_b)`、速度 `s=(V/V_b)^0.15`；电磁矩阵保持N=5.25、s=1，更高价值提高续航和速度，新增矩阵与原版共用公式。扩容的六档接纳集合独立，不因此扩大。

备用食物保存一类未食用矩阵，消化槽保存当前件及剩余能量、单件增产点。点燃逐件扣库存和增产点并登记一次消费；能量为 `N×(1+Cargo.incTableMilli[min(inc,10)])`，不区分Productive。速度只取当前件，增产点不提速；无消化物时倍率1并按耐久效率运行。当前件耗尽才接续，不建立混合营养池。

高级塔在AdvancedState内用独立字段保存消化物和double剩余比例，加载按当前估值恢复等比例能量；既有AdvancedRuntime的-4布局保留读取。联机全量/增量使用相同的新序列，协议修订19拒绝不一致的客户端。

工作能耗为成功轮实际消耗的主料件数之和，每件1点；失败回流、催化剂和无关直通不计。一次结算超过当前能量时逐件接续燃烧，不丢弃上一件的剩余能量；备用食物耗尽后不保存能量欠账，断粮后按耐久降速。无配方、缺主料/催化剂或输出堵塞时每秒消耗 `MaxBeltSpeed/20=30/20=1.5` 点，按每帧1/60结算，不乘速度倍率。可工作但未满一轮进度时不额外扣待机能量。

每帧处理前保证可用食物进入空消化槽，结算后再接续空槽。消化物有能量且同种备用食物非空时，每秒恢复最大耐久0.5%，至少1点；异种旧库存待排时不充当当前件的恢复储备。仅剩消化物时不恢复也不衰减；消化物和备用食物皆空时满耐久360秒损毁，每秒按最大耐久的1/360累计差额扣除整数耐久，连续360次秒结算累计扣除恰好一个最大耐久。原版无人机恢复关闭。主动拆除返还备用食物及其他缓存，消化物销毁不返还；建筑损毁不返还。

## 4. 研究与发现

### 4.1 样本与概率预算

配方分级：BasicMineral与TowerCultivation为普通；EmbryoBreeding及mineral-memory:*源点重构为传说；其他生产配方为稀有。普通配方在首遗物后且原版矩阵科技资格达到max(1,ResearchStage)时自动恢复；培育还须首次实际生产电磁矩阵。不另收样本、不依赖探索。已解锁状态永久保留。稀有配方使用样本研究；传说不进入样本发现与电路板制样候选。

`WorldviewRecipe.AnalysisItemId`定义稀有配方的唯一解析样本，`ResearchStage`定义所属阶段。探索与信号记录样本关联，独立电路板制样保留自己的线索入口。仅已有待解析线索的样本允许研究；无线索输入不推进、不损毁、不自动发现内容。既有已发现及完成记录保持。完成前不展示未知结果。共享进度0～9999，满10000从已经取得线索、尚未完成的同样本内容中随机选择一项。

| 阶段 | 开局 | 蓝 | 红 | 黄 | 紫 | 绿 | 白 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 普通样本成功次数期望 | 100 | 200 | 300 | 1000 | 3000 | 8000 | 20000 |

特质独立成功次数期望20000。普通样本使用连续价值系数 `q=1+log10(max(1,v))`，v读取ItemManager.itemValue；无有效估值按1处理。每次成功概率 `p=0.03/q`，损毁概率 `d=min(0.15,0.04+0.02×q)`，侧面流回概率 `1−p−d`。增产点不改变研究概率，侧面流回保留增产点；成功样本从正面返还，沿基础产物口径不携带增产点。批量共用一个U，成功数 `floor(k×p+U)`，损毁数 `floor(k×(p+d)+U)−成功数`，保证结果互斥且总数不超过k。

只有实际参与研究的成功次数推进进度，每次成功的期望推进量为 `10000/当前候选平均预算`，批量推进使用期望取整，支持小于一点的增量；多个阶段或种类共享样本时，完成后重新计算候选平均预算。成功同件样本进入正面实物缓存，既不计真实消费，也不计新制造产量；损毁才计样本消费且不推进。无可研究内容时不判定损毁；本批因内容完成未用于研究的成功样本及对应比例的损毁样本一并侧流，实际损毁数为 `floor(原损毁数×实际使用成功数/原成功数)`，仅在末批有未使用成功时折算。同批不发现未知内容。解析记录按阶段和稳定内容身份排序，三态变化不改位置：当前可探索且无线索的记录灰色匿名，不公开样本或结果；已有线索显示样本及该物品共享进度；完成保留原位，显示结果和完成色。普通配方、传说、科技及阶段资料不进入该目录。内部预算按成功次数计，不向玩家公开；整数进度及批量末端允许离散偏差。

每类高级塔亚空间库存首次达到1000后保留特质探索资格；库存后续下降不撤销。首次千塔生成献祭任务，回收后开放献祭。有已知配方或特质时优先解析，无候选才按4.4塔体献祭处理。

### 4.2 阶段恢复

矩阵资格以原版物品解锁状态判断。每阶段注册唯一 `stage:1`～`stage:6`，源点以2%成功率参与恢复，不损毁；仅成功且实际参与当前阶段的源点消耗并累计，失败源点携增产点回流。内部成功投入需求为10、40、120、300、600、1200，达到需求恢复该阶段，页面只显示百分比，不显示投入数或预算。完成一次开放该阶段所有普通成长科技资格，特质还需自身研究，矩阵成本仍逐项支付。

解析塔优先处理最低未恢复的已开放阶段。每批成功源点最多使用当前阶段的剩余需求，其余流回；同批不跨阶段，也不计入献祭。

### 4.3 Memory分钟献祭

已开放阶段全部恢复、且千塔献祭已开放后，解析塔按4.4处理率收取Memory，将实际吃掉数计入游戏完整分钟；其余保留增产点侧流。否则无用途Memory原样流出。

`B(next minute) = min(0.75, 0.05×floor(sqrt(M)))`

M为上一完整分钟实际献祭Memory数。三类高级塔统一受益，当前分钟只累计，不即时叠加；跨过空分钟则加成归零。存档记录当前分钟编号、当前投入及已经发布的B。Memory生产变体不向该计数器登记。

### 4.4 早期自动化与残页

纯消耗入口统一按每次经过的件数k先结算 `processed=floor(k×0.08+U)`；其余 `k−processed` 保留增产点侧流。处理件数再按下表结算成果，不受增产点加成。

| 入口与资格 | 被处理件数的结算 |
| --- | --- |
| 六种主线矩阵，通信及首遗物已恢复 | 先尽量进入本档全局扩容缓存；未被接收的已处理件数各以1/N概率产1源点 |
| 残片，探测器已恢复 | 各以2%概率尝试增加1个普通广播，仍受上限和冷却限制 |
| 高级塔，无研究候选且千塔献祭已开放 | 各以2%概率正面产1源点 |
| 源点，已开放阶段均恢复且献祭已开放 | 全部计入本分钟实际投入，不产生实物 |

矩阵每批只抽一次8%：先供料，再用剩余已处理数量结算源点，不对未处理矩阵另抽献祭。N按蓝至白依次为100/60/40/25/15/10；对应每次经过的源点成功率为 `0.08/N`，无成果消耗率为 `0.08×(1−1/N)`，侧流92%。源点阶段需求乘N折合平均1000蓝/2400红/4800黄/7500紫/9000绿/12000白的实际矩阵消耗，不含回环经过次数。达到终极仓储或扩容数值上限后，矩阵仍可沿该入口献祭；已供料件数不再换源点或登记分钟献祭。残片及塔体每次经过的成果率0.16%、无成果消耗率7.84%、侧流92%；平均每次广播生成尝试或每份源点实际消费50件。源点从正面输出，广播受上限及冷却限制，生成失败不积欠。

红矩阵资格起，电路板每次经过成功率1%、损毁率3%、侧流96%，三类结果共用同一个随机偏移划分。成功时从当前阶段未恢复的置换配方中等概率选择候选，正面输出一件该配方AnalysisItemId样本，并登记线索；成功制样和损毁均消费电路板。批量按期望取整，同一批产出的样本共用一次等概率候选选择。全部相关配方恢复后停止处理，电路板全部原样流出。该入口不参与高级生产配方目录。

二、三层普通地点有25%概率恢复一份残页。优先补全三份百科残页，之后从当前阶段未恢复传说配方中随机直接恢复一项；没有可恢复项则继续普通奖励。百科残页按固定顺序恢复，并保存于Research已恢复内容集合，稳定身份encyclopedia:1～3。前两份分别补全生命工业和源点/物流说明，第三份补全传说机制。传说另一途径：献祭已开放后，每个完整分钟实际投入至少50源点，恢复当前阶段首项未完成传说配方；同分钟最多一项，不额外扣物，既有成功率增益照常结算。原型奖励按既有塔型去重并在研究锁外发放。

## 6. 亚空间与物流

估值统一使用ItemManager.itemValue。MineralValues对所有已加载岩石主题等权平均：普通权重为VeinSpot×VeinCount×VeinOpacity；稀有出现概率q取非出生星系RareSettings，连续追加概率p的矿群期望G=Σ(i=0..11)p^i，数量与丰度系数为a，则该主题权重为(1−q)×普通权重+q×(原矿群数+G)×a²。普通恒星采用中性稀有指数1，不按实际星图重算。特殊星体使用固定稀缺权重：白矮星2/64，黑洞与中子星合计2/64，按原版额外矿群规则计入金伯利、分形、光栅与单极。它是估值参考权重，不是实际矿量预测，不创建银河。铁铜平均权重为基准，两者价格固定1，其他矿价=max(1,round(基准/自身权重,2))。天然矿价不由工业反向配方覆盖。

源点取全部已定义珍奇重构配方的最大净产出价值，扣除成功轮催化剂期望损耗，向上取整到100；失败回流不额外乘成功率。残片=原胚价值2000×1%/10%=200。源点、残片和实体元数据使用显式身份排除普通复制，不用maxValue充当权限；手动上传、双击整理和丢弃回收统一接受全部已注册实体物品，并保留原物品数量与增产点。maxValue仅表示未获得有限估值。

库存与增产点为long数组，每件最多10增产点，使用非负饱和运算。普通容量为 `floor(基准件数×S)`，S为永久容量倍率，初始1，数值上限1000000。建筑及无有效估值物品的基准为 `10×max(1,StackSize)`；其余物品取该底线与 `10000/max(1,log10(itemValue+1))` 的较大值。物品间容量独立；容量变化不截断旧库存。

取得首遗物及通信后，基础解析塔接收蓝、红、黄、紫、绿、白六种主线矩阵，沿4.4先抽低概率处理件数。被扩容接收的每件转为对应档位1秒供料，增产点不额外加速。每档全局缓存最多60件，多塔共享；已处理但超出缓存的件数按4.4换源点，未处理矩阵保留增产点侧流。主机每个游戏秒同时消费每个有供料档位1件，各档独立增长，不补算离线时间。

六档权重w为1/2/4/8/16/32，各档增量S_i从0开始；以分钟计，`dS_i/dt=0.1×w/(1+(1+S_i)/10)`，每秒精确更新 `S_i'=sqrt((S_i+11)²+w/30)−11`。总倍率为 `min(1000000,1+ΣS_i+S_overflow)`。累计溢出价值V不随库存增减回退，每个游戏分钟更新一次 `S_overflow=min(999999,sqrt(1+V/100000000)−1)`，不产实体。达到总倍率上限停收；终极仓储停收停耗；倍率35开放终极仓储任务。仓储页六个固定图标分别标记生效，问号仅说明各档独立累积，不显示扩容倍率或速率；悬停物品仍显示实际库存和独立容量。

入库来源由StorageSource显式区分。Manual允许超容实体；BasicTower及UnlimitedStation先按容量存入，超额件数乘统一价值加入V；LimitedStation按min(容量,上传目标)接收；Assembly只按容量接收。StorageReceipt分别返回入库、折算、拒收的件数与增产点，上游扣入库与折算部分，拒收留原处。未知估值超额拒收。通知研究与取得门槛只认Stored，在库存锁外执行；客户端不结算自动上传或扩容，使用主机快照。

终极仓储容量采用 `long.MaxValue/10` 数值安全边界，界面显示无限。普通满仓拒收，探索超额物品可提取；数量与增产点按实际搬运量拆分。

手动存取、基础塔上传无额外能耗。物流交互站右上为关闭上传/有限上传/无限上传，默认有限上传；右下为关闭下载/开启下载，默认开启下载，两个按钮固定保留。左侧原版物流供需独立。双向开启沿用上传优先，每槽每轮只执行一个方向；下载不自动补喷。旧Sync/Upload/Download及容量编码保留含义，新增Disabled=3表示双向关闭，存档、蓝图和复制粘贴沿用两整数格式。联机主机合并单方向命令，以StationModes全量块同步设置。

`单件耗能 = sqrt(itemValue)×10000×InteractEnergyRatio×SubspaceEnergyRatio`，能效倍率见7.3。

每轮先筛选已设置物品、对应方向开启、达到阈值且源端有可用物资和目的端可接收的请求，再按有效槽数均分本轮站内电量。固定两遍扫描并复用请求缓冲，不多轮再分配；未用电量留站。零库存下载槽仍可参与。最终按实际搬运量向上取整扣电。物流交互站制造使用对应原版站1、基础矿物塔4、基础解析塔4。

### 6.1 元数据额度

MetadataExtraction只读history.propertyData.totalProduction内6001～6006的生产峰值，避免调用会插入零条目的GetItemProduction。各类可用额度=max(0,当前峰值−FE已使用)，不减原版消费。每1额度可手动提取1件实体元数据8178或兑换1件能量碎片5206，每次最多100；两种用途共用扣账，直接送入亚空间，可超存，不折算溢出。实体元数据统一估值2，与兑换能量碎片相同；显式排除普通复制，允许整理及回收存入亚空间。5206及8178在来源闭包前以RegisterExternalSource登记，黑雾相邻转换保留30308～30317及显式研究阶段，30307不注册。

元数据保存于文明域MetadataState，已用额度、峰值、去重流水及跨档倍率分别为独立字段；矩阵额度按稳定物品ID恢复，集合逐项隔离。既有Metadata版本1保留读取。主机在亚空间库存锁内提交入库与扣账，离锁后通知研究；客户端只发带世界身份及唯一流水的命令，不预发实体。重复流水不重扣，切档清空所有内存状态。跨档C取propertySystem已加载星图记录中6006生产峰值，按seedKey去重取最大并排除当前星图，不读取消费，不扫描其他存档文件；M=1+C/C0，配置Monument/CrossWorldMetadataScale默认100万。

### 6.2 生产与联机取物

亚空间不承担下单生产。玩家自行搭建产线或配置塔厂机器、产品与原料槽；FE不建立订单、配方树、预留账本或共享生产队列，不自动选择机器和切换配方。物流交互站按实际槽位数组执行亚空间存取。

FE不注册装配节点、模型或配方，不读取订单、不返还历史订单投入，也不保留旧实体占位。

联机取物使用MaterialLeases预授额度：主机先从自由库存划出实物，客户端的同步Take只能消费已授部分。制造/建造预检查按缺口异步申请，初始至少一组，同一额度累计最多100万件，每连接最多256种，首次申请需一次往返。物品不必先经过背包，手动提取保留手中/背包偏好。客户端以世界身份、唯一额度ID和累计消费件数/增产点核销，消费包先于调用方后续游戏动作发送；普通负增量包不能替代主机授权。额度与实际背包/物流包合计才是可消耗量，共享副本总额不直接计入。

额度空闲5游戏秒或达到累计上限后，客户端先停止使用并提交最终累计消费，主机收到才返还未用额；旧回执与重复核销不能重发物品。断线返还在Nebula消息队列确认排空后处理，仍可核销断线前已排队的既有额度；不按时间强制回收活动客户端的额度。LeaseBalances子块逐项保存未核销余额，物品、余额和增产点分别分块；既有MaterialLeases版本1保留读取。磁盘导入把余额恢复为自由库存并丢弃旧会话身份，网络快照仅跳过该块，避免把同一额度重新加入自由库存。切档清空，正常结束会话返还未用额。真实背包自动交付等待期间暂缓额度消费，避免旧交付背包快照遗漏新领取物料。

### 7.4 丰碑

高级转化塔在白矩阵阶段恢复丰碑制造：每成功轮次1矩阵+1太阳帆→10对应矩阵的丰碑帆；1实体元数据+1小型运载火箭→1丰碑火箭。两类基础成功率均为8%，失败主料侧流，食物仍独立供养。每种矩阵使用独立弹药身份；最终合法来源闭包中的所有Type=Matrix及5201组成固定挑战集合，未解锁或未投入种类仍计零。

原版弹射器（含星环重型）与火箭井接收专属弹药，保留供电、装填、瞄准、蓄力、冷却与发射视觉。专属发射不结算普通太阳帆、戴森结构或其他巨构奖励。丰碑火箭抵达时，红巨星贡献4、蓝巨星2、其他星体1；全档贡献和每满100提高永久等级L。每座有火箭贡献的星系需求为100×矩阵种数×max(1,本座贡献/100)。丰碑帆抵达后寿命600秒，按来源记录到期批次，需求跨星系相加。

令各合法矩阵的全档未过期在轨数量为x_i，k为种数，μ为均值。μ=0时均衡B=0；k=1且μ>0时B=1；其余B=clamp(1−Σ(x_i−μ)²/(k×μ²×(k−1)),0,1)。该量与同比扩大规模无关。全档供帆率=min(1,在轨总数/需求总数)，无建设或无需求为0。接收站共享专属材料预算2×L×M/分钟×供帆率，按有效接收站平分；停收或满仓的份额不转给其他站，不累积离线产能，单站不足整件余量保留。

每100件专属材料由既有解析系统消费，使全档永久成长n增加1；成功率100%、损毁0%，不足100件的余量保存。跨档倍率M沿6.1元数据定义。令基线r0为CurrentVanillaRecipeTimeRatio，额外增益F=(1+0.15L+0.02n)×M，实际r=r0/(1+B×(F−1))；尚未建成L=0时r=r0。对全部有效普通注册配方应用TimeSpend=max(1,ceil(加载最终原始时间×r))，排除分馏及FE高级展示原型，未解锁不例外、不额外解锁。不叠乘当前时间，不设旧0.2或16级上限；更新制造台及非科研实验室执行缓存。非空目标集合全部为1帧时，按已有世界资格去重记录通关。

帆物品与展示配方按最终矩阵原型后注册，使用原版图标索引容量内的稳定编号，同时排除已占用的物品与配方ID；编号发生外部重映射或冲突时报错。发射井空仓恢复普通弹药入口，弹射器每帧在原版六格需求的五个额外格中轮换矩阵帆，装有库存时只收同种；普通弹药仍沿第三方当前规则。FE帆通过原版方法副本保留瞄准、轨道、供电和节奏，FE火箭通过相同充能/冷却参数抵达丰碑轨道，不依赖普通未建节点。

阶段恢复页在白矩阵阶段展示丰碑记录及全矩阵在轨数量。射线接收站窗口提供结晶接收开关，已有整件产物取尽后才能切换；模式沿原版组件保存。有效接收站须位于有建设贡献的星系、有电网及正接收强度；全档份额再乘不大于1的当前接收强度，保留原版镜头、预热和出料空间约束。接收不请求普通戴森能量，满仓份额丢弃，不能以后补领。

## 9. 存档、迁移与联机

### 9.1 当前格式

顶层保存版本固定为10；稳定块为Stacking、Building、Item、Civilization3、UI、Station。格式1/2走2.2专用入口；其他顶层版本均尝试通过SaveUtils读取标签化块，不在GameData加载前或FE导入入口按版本拒绝。导入前清理上一存档状态；按标签选择当前处理器，按长度隔离每块，未知标签跳过，缺失数据保持当前默认值。块内容无法读取时记录块名及原因并继续其他块；块数量、标签或长度损坏导致无法确定下一块位置时，停止当前块列表，保留已恢复数据，嵌套列表以外的块继续读取。恢复后同步当前运行状态，不将部分恢复表述为完整恢复。字段改名可在读取声明中注册历史别名：当前名优先，其次按别名声明顺序选择，每个字段只执行一次；写入仅使用当前名。同级命名块的物理顺序不影响匹配，处理器按当前注册顺序执行。原始值序列内部仍有顺序，独立状态须继续拆成命名子块。集合保存实际数量及逐元素长度，未知元素或元素内容失败不影响后续元素；边界损坏时停止当前集合。原版配方时间由加载基线、堆叠与丰碑实时计算，不持久化废弃升级字段。

Civilization3内Research保存代际、完成资格禁用标记、样本关联、已解析内容、共享进度、原型授予去重、取得塔型与千塔里程碑。ProgressionState子块分别保存献祭开放标记、分钟编号/投入/增益和实际Memory投入；阶段数组保存数量及稳定矩阵ID。既有Progression顺序布局保留读取。

文明主机快照包含Civilization、DataCenter及堆叠。高级塔真实状态沿用每秒广播和中途加入补发。新增阶段、分钟、任务及奖励记录通过现有业务导出进入快照。

CivilizationActionPacket的动作1为认领、3为邻近发现，旧动作2不再处理。主机从连接读取位置与星球，验证实际距离；认领以点位身份防重，发现不接受客户端清单。

真实背包交付使用MemoryDeliveryPacket/ResultPacket。客户端验证本地Storage格式后暂存源点，发送唯一Guid、世界身份、地点、实际件数/增产点及交付前背包快照；主机重建并验证该扣除，按剩余需求写回Nebula连接背包、记录流水并推进任务。相同流水只回原结果，身份/地点/摘要不符则拒绝。客户端只退还未接收部分并确认，重复回执不再退款。等待确认期间，Nebula的机甲整包仍更新能量等字段，但保留已经结算的Inventory，避免暂存状态覆盖真实接收结果。断线结束时不盲目退还待决客户端物品，重连沿Nebula主机背包状态恢复；FE不另写Nebula磁盘文件。未找到兼容入口或本地快照不符合格式时，不扣物并报告不可用。请求5秒未收到回执时沿同流水重发。

交付前库存快照限定原版Storage版本2、1～10000格、精确40+20×格数的字节长度，先检查边界再导入。每次交付最多2400件、增产点至每件10，位置不从请求提供。网络处理沿Nebula主线程包队列执行，扣物、流水和任务进度同锁结算。

ExplorationRecoveryPacket传已结算的kind/contentId/itemId/count/quality，不依赖文明快照先到；客户端检查点位类型、质量范围与非负数量后，只将事实副本加入本地提示队列。类型决定确认弹窗或浮现提示，标题、正文与物品名称均由本端生成；主机拒收客户端发来的此类提示。联机版本在插件版本后附加协议修订18及丰碑弹药身份表SHA256并精确匹配，主机和客户端须共同采用整批越阈值、同种供养、随堆叠增长的食物缓存及对应库存安全界限，避免旧端裁剪合法库存。双方使用独立字段与逐元素边界的快照布局，避免把旧顺序载荷误读为新布局。存档切换清空提示队列。

丰碑客户端不登记抵达贡献、不生成结晶。专属弹道通过MonumentProjectilePacket从主机单次下发，普通Nebula太阳帆/火箭包不代替来源身份；客户端只补发射视觉。MonumentReceiverPacket只请求主机核对本星球真实设备和空仓后切模式，文明快照覆盖接收库存与预算，中途加入同样同步。主机拒绝客户端提交弹道或成长值；跨世界包不处理。

## 10. 兼容与边界

Genesis Book、Orbital Ring等保留科技布局、物品和教程接线；第三方集成不拥有业务状态。普通资源分类与高级置换目录的边界不因探索而改变。深空来敌启用时，堆叠科技行在当前布局纵坐标额外+8；原版布局由-107移至-99，与元驱动链保留一行间隔。

仅按秒同步成长效果缓存，运行态不重新遍历特质科技；探索广播、本地可探测集合和档案按变更缓存。UI与缓存不改变主机结算权。
