# Fractionate Everything 游戏设计规格

本文将 `GAME_DESIGN.md` 的体验规则落实为当前实现的数值、公式、目录、时序、持久化与联机规范。除明确标注兼容别名外，本文件只描述当前行为。

## 1. 设计目标

### 1.1 格式与单位

- FE 自有存档版本：`12`；版本 11 可按明确迁移规则读取。
- 游戏逻辑时间：每秒 60 tick。
- 数量单位：件；容量单位：组数乘物品原版 `StackSize`；能量单位：J。
- 概率批量结算统一使用 `floor(expected + U)`，其中 `U` 为 `[0, 1)` 均匀随机数。

### 1.2 系统真源

- 配方定义与稳定身份：`RecipeManager` / `WorldviewRecipe`。
- 随机内容发现：`ResearchManager`。
- 探索信号：`ExplorationManager`。
- 确定性成长：`GrowthTechnologyManager`。
- 亚空间库存：`DataCenterInventory`。
- 基础塔运行：`FractionatorRuntime`。
- 高级塔运行：`AdvancedFractionatorRuntime`。
- 联机结算：主机上的上述同一业务对象；Nebula 层只传递请求、快照和合法增量。

## 2. 世界观与开局

### 2.1 两个关键信号

玩家首次生产电磁矩阵后，程序从原版 `MilestoneProto` 中按 `MST_ItemFirstProduction` 和物品 ID 6001 动态找到对应里程碑。里程碑完成时启用遗物探测器，并在出生星生成 `FirstRelic` 点位。该点位显示为 `关键信号1`：

- 永久存在，直到认领。
- HUD 公开出生星名称，并持续显示无方向的遗物探测强度。
- FE 不调用 `PlayerNavigation.Navigate`，不建立位置标记，也不创建移动命令。
- 玩家进入以点位为球心的 120 m 范围时自动认领。
- 从旧版本读入后，仅当原版自动导航仍处于运行状态，且星球和局部目标都精确匹配当前首遗物时，调用 `PlayerNavigation.Abort` 清除遗留状态；其他玩家导航不处理。

首遗物认领奖励直接写入亚空间且可突破常规容量：

| 内容 | 数量 |
| --- | ---: |
| 基础矿物塔 | 10 |
| 基础解析塔 | 10 |
| 通用原胚 | 20 |

同时执行：

- 直接建立亚空间通信和主面板访问，不注册或解锁“分馏亚空间网络”科技节点。
- 直接解锁基础矿物塔和基础解析塔制造配方。
- 直接解析石矿与铁矿的基础自身复制配方。

首遗物认领后，当主机玩家的 `mecha.thrusterLevel >= 3` 时，在出生星系另一颗星球生成 `PlanetDetector` 点位。目标选择排除出生星，优先固态星球，再按轨道距离由远到近选择；正常星系没有其他候选时才退回出生星。该点位显示为下一全局 ID 对应的 `关键信号{ID}`，直接公开目标星球名称。玩家进入同一点位认领范围后恢复星球探测器，初始化第一次普通信号定时周期；此后 Frag 和定时路径才允许生成普通未知广播。

### 2.2 已玩过档案补给

本地 BepInEx 配置项 `Progression/HasPlayedFractionation3` 为 `true` 时，首遗物额外：

- 解锁基础物流、改良物流、高效物流和集装物流四项原版科技。
- 发放极速传送带 1000 件。
- 发放集装分拣器 200 件。
- 当前存档采用已玩过堆叠路线；该路线值同时写入存档，不在切档后重新按本机配置推断。

只有使用当前存档格式的存档同时满足“取得过三类高级塔”和“当前全局堆叠达到 20”时，才把该配置写为 `true`。从旧格式迁移的存档不能触发。

## 3. 五塔工业

### 3.1 稳定原型身份

| 塔型 | Item ID | Model ID | 配方类型枚举值 | 供能 |
| --- | ---: | ---: | ---: | --- |
| 基础矿物塔 | 8123 | 653 | `BasicMineral = 3` | 电网 |
| 基础解析塔 | 8122 | 652 | `BasicAnalysis = 2` | 电网 |
| 高级矿物塔 | 8125 | 655 | `AdvancedMineral = 5` | 矩阵营养 |
| 高级交互塔 | 8121 | 651 | `AdvancedInteraction = 1` | 矩阵营养 |
| 高级转化塔 | 8124 | 654 | `AdvancedConversion = 4` | 矩阵营养 |

基础塔制造配方 ID 为 1063、1064。旧中文常量可映射到相同物理 ID，但不得注册额外塔；不注册高级解析塔。

### 3.2 基础塔

基础塔单输入、自动识别，不保存选定配方。缓存以堆为单位，一堆的件数等于当前全局堆叠：基础输入、流动输出和产物输出容量均为 20 堆，即 `20 × 当前全局堆叠` 件。

从传送带收取货物前读取带尾真实堆叠，只有整批加入后输入件数不超过输入容量才取货。旧档中已有的超量会继续流出；降回上限前不再收料。

基础矿物配方候选由原版矿脉产物、明确列入的普通资源和全部 `EItemType.Resource` 项组成，并排除：

- 珍奇目录：可燃冰、金伯利矿石、分形硅石、光栅石、刺笋结晶、有机晶体、单极磁石。
- 黑雾矩阵至能量碎片区间。
- 无有效价值或不存在的物品。

每张基础矿物配方为：

- 输入同物 1 件。
- 每轮成功率 5%。
- 成功输出同物 2 件，净增 1 件。
- 失败的输入原样进入流动输出。
- 通用损毁率为 0。

基础解析配方只为以下有实际用途的物品建立入口：研究目录中至少一项内容可由该物品承载、Frag，以及三类高级塔。普通方向只有在探索已经确定该物品承载一项尚未解析的具体内容时才会消耗输入；Frag 在星球探测器恢复后才尝试生成普通信号，恢复前原样流出；高级塔始终可处理。其他物品没有解析配方并按非目标物原样流出。

当正面端口为输入且两个侧面端口均未连接时，两座基础塔进入正面上传路径。上传前按带尾真实堆叠检查亚空间是否可完整接收；容量不足时不拆分、不取货。基础塔上传不额外计传输能耗。

### 3.3 高级塔输入与状态

每座高级塔按 `(planetId, fractionatorId)` 保存独立状态：

- 选定配方稳定整数 ID。
- 反应输入及其增产点。
- 矩阵食物及其增产点；食物槽同一时间只存一种矩阵。
- 产物。
- 流动输出及其增产点。
- 营养、最近一次食物层次、产物轮转游标和流动/产物优先位。

每个物品在每类缓存中的上限均为 20 堆，即 `20 × 当前全局堆叠` 件。输入时顺序如下：

1. 若物品是矩阵且食物槽可以接收，优先填充食物槽。食物槽只有一个位置：槽内已有某种矩阵时只接收同种矩阵；槽空时接收最先到达的矩阵。不能进入食物槽的矩阵按其余物品规则处理。
2. 若物品属于当前配方，先将反应输入补到两轮用量。
3. 其余数量进入流动输出。
4. 流动输出已满时，当前配方输入才继续进入反应缓存，直到缓存上限。
5. 与当前配方无关的物品只进入流动输出。

每项低概率消耗输入仍需至少存在一轮用量才能开工。切换配方时，属于新配方的输入和营养保留；不属于新配方的输入、旧产物和无关流动物优先排出，不等待凑满堆叠。

### 3.4 批量反应

每个更新周期先按真实输入数量和缓存空间计算可执行轮数 `k`。进度增长率为：

`rate = k * foodSpeed * durabilityEfficiency`

其中营养大于 0 时 `durabilityEfficiency = 1`；营养为 0 时取当前耐久百分比。进度每满 60000 结算一轮，因此输入货物从 1 件增至 20 件时，可用轮数、加工推进与工作营养消耗同步放大 20 倍。可执行轮数同时受以下条件限制：

- 所有 100% 消耗输入的现有数量除以每轮用量。
- 每项低概率消耗输入至少有一轮用量。
- 失败流出缓存有空间容纳一轮全部普通输入。
- 每项可能产物有空间容纳按上界估算的一轮产出。

一批 `k` 轮使用当前塔种的献祭加成 `B` 计算有效成功率：

`p = min(1, 0.20 * (1 + B))`

`success = min(k, floor(k * p + U))`

`B` 的来源和更新公式见 4.3。输出空间上界也使用同一有效成功率，避免献祭加成使实际产物越过缓存限制。

对 100% 消耗输入，一批先扣除 `k * count`：成功轮对应数量登记消耗，失败轮对应数量和按比例拆分的增产点进入流动输出。对低概率消耗输入，只按成功轮结算：

`consumed = floor(success * count * consumeProbability + U)`

每项产物独立结算：

`produced = floor(success * outputPerSuccess + U)`

旧配方物品与无关物品拥有最高排空优先级，不等待凑满堆叠。正常运行时，当前流动输出和当前产物交替获得出口机会；多个产物按待输出堆数加权轮转。全局堆叠大于 1 时，当前配方的流动输出和产物必须凑满一堆才输出；当前配方输入全部用完后允许释放不足整堆的尾料。堵带时保留物品，不丢弃。

### 3.6 营养与耐久

| 矩阵 | 营养/件 | 速度倍率 |
| --- | ---: | ---: |
| 电磁矩阵 | 1 | 1.0 |
| 能量矩阵 | 2 | 1.1 |
| 结构矩阵 | 4 | 1.2 |
| 信息矩阵 | 8 | 1.3 |
| 引力矩阵 | 16 | 1.4 |
| 宇宙矩阵 | 32 | 1.5 |

- 营养上限：1000。
- 工作消耗：每个等效加工轮消耗 0.02 营养；缺料或堵塞待机消耗 0.002/s。
- 同一 tick 转换多层矩阵时，速度层次记录本批最高层。
- 营养大于 500 时，每秒恢复最大耐久的 0.5%，至少 1 点。
- 营养在 `(0, 500]` 时不恢复也不衰减。
- 营养为 0 时，加工效率等于当前耐久百分比，并且每秒损失最大耐久的 1%，至少 1 点。
- 高级塔把原版 `hpRecover` 清零，营养恢复直接修改真实 HP。
- 满血且营养充足时不创建无意义战斗状态；饥饿时可创建状态并持续扣除。
- 主动拆除返还输入、食物、产物和流动物；战斗损毁只清理状态，不返还缓存。

## 4. 研究与发现

### 4.1 目录、具体探索与承载物品

研究内容使用稳定字符串 ID。每张非解析配方进入研究目录，并记录全部输入、非高级塔产物及基础矿物配方的相关普通资源作为可选承载物品。科技方向使用以下稳定内容 ID，并统一由 Memory 承载：

- `technology:super-compression`
- `technology:subspace-capacity`
- `technology:subspace-efficiency`
- `technology:exploration-signal`
- `technology:planetary-subspace-interaction`
- `technology:interstellar-subspace-interaction`

三项高级塔特质内容 ID 为 `trait:advanced-mineral`、`trait:advanced-interaction`、`trait:advanced-conversion`，只由对应高级塔承载。1000 座库存门槛只让该特质进入探索候选。

探索候选按内容而不是物品生成。每个普通探索点从当前层级允许、尚未探索、尚未解析且没有活动点位占用的具体内容中选取一项，再从该内容合法承载物中选取一个物品。高级塔只承载自身特质，不承载目录中的其他内容。认领后保存唯一映射 `contentId -> itemId`；同一内容不会同时进入多个物品槽。

内容层级用于控制探索候选节奏，不用于解析槽内二次筛选：

| 层级 | 内容 |
| ---: | --- |
| 0 | 基础矿物自身复制、超级压缩技术 |
| 1 | 培育高级交互塔、亚空间扩容、探索信号增幅 |
| 2 | 其余高级塔培育、珍奇催化、置换回收、行星亚空间交互、亚空间存取能效 |
| 3 | 三类原胚繁育、星际亚空间交互 |
| 4 | 三类高级塔特质 |

当前可生成内容的层级不高于“已解析最高层 + 1”。普通信号在认领前统一显示为 `信号{ID}`，不公开内容或承载物。

### 4.2 共享解析槽结算

每种承载物品只有一个 `DirectionProgress[itemId]`，范围 0..9999。普通方向每件输入有 2% 进度成功率：

`success = floor(count * 0.02 + U)`

- 普通内容每次成功增加 500/10000，即 5%；期望约 1000 件完成一项。
- 当前该物品所有候选均为塔特质时，每次成功增加 100/10000，即 1%；期望约 5000 座塔完成一项。
- 候选只包含映射到该物品、已经探索且尚未解析的具体内容。
- 进度满时从当前候选等概率选择一项；只有一个候选时结果确定。
- 批量成功可以跨越多个内容；每次完成后立即重建该物品候选。
- 完成内容后全局解析该稳定 ID，并从全部目录关系移除；配方产物不会自动把关联池整体加入解析槽。
- 科技方向完成解析后，对应整行节点同时显现；解析本身不赠送任何科技等级。

普通物品没有候选时不被消耗并原样流出。高级塔例外：有映射到该塔的已探索特质时只推进解析且不产生实体产物；没有候选时转为献祭，仍按每件 2% 成功率结算，并从正面产出等量 Memory。解析和献祭不会在同一批输入中同时发生。

Frag 只有在星球探测器恢复后才可解析，每件有 2% 概率立即尝试生成一个普通未知广播，不使用共享内容槽。探测器恢复前输入的 Frag 不被消耗，按非目标物原样流出。

首次解析某一高级配方类型时，亚空间额外获得该类型高级塔 1 座，并记录“已取得”。同种高级塔在亚空间库存中首次达到 1000 座时，只永久满足该塔特质的探索门槛；库存随后降低不撤销。初始容量只有 300 座高级塔，玩家至少需要完成三级亚空间扩容才能达到门槛。之后高级塔常规来源为培育配方或繁育循环。

### 4.3 Memory 与献祭加成

高级塔通过基础塔正面、物流交互站或手动操作上传时按原物品及真实增产点进入亚空间，不转换为 Memory。Memory 由基础解析塔的高级塔献祭结果产出，用于承载六条普通科技方向，也作为复合单极磁石配方原料并按成功轮 100% 消耗。

高级塔有已经探索、尚待解析的自身特质时只推进共享槽，不产出 Memory；没有该候选时才执行献祭。首次取得高级塔只记录取得状态；达到 1000 座也只开放特质探索候选。

每类高级塔独立统计最近 60 秒内基础解析塔实际消耗的献祭数量，不按 Memory 产量计数。每秒更新一次该类塔全部高级配方的成功率加成：

`rate = 最近 60 秒同类塔献祭数量 / 60`

`bonus = min(0.75, floor((sqrt(rate) / 10) / 0.05) * 0.05)`

`effectiveProbability = min(1, baseProbability * (1 + bonus))`

加成以 5% 为档，上限 `+75%`；不同塔种不共享速率。60 槽时间窗口、当前加成和库存门槛完成标记进入存档与主机文明快照；客户端只使用主机同步结果。

## 5. 探索

### 5.1 主线门槛与生成节奏

- 关键信号 1 和关键信号 2 按 2.1 的确定条件各生成一次，不占普通点位星球额度。
- 星球探测器恢复前，普通信号定时器保持未启动，Frag 也不能生成普通信号。
- 探测器恢复时设置第一个普通信号周期；基础周期为 60 分钟游戏时间。
- 探索信号增幅等级为 `L` 时：`interval = max(10 min, 60 min * 0.9^L)`。
- 每发现一项研究内容，只把当前 `nextTimedGenerationTick` 提前 3 分钟；调整后距当前时刻不得少于 10 分钟。
- 定时器到期但没有有额度的星球时，不推进下一周期；出现新额度后仍可立即生成。
- 探测器恢复后，Frag 每产生一个探索点，立即独立尝试生成一个普通信号。

### 5.2 候选、额度与内容

星球探测器恢复要求推进等级至少为 3，因此普通未知广播从全银河星球中选择；研究内容概率固定为 30%，其余为资源点。如果具体内容候选池为空，研究点自动退化为资源点。

星球额度与资源倍率：

| 区域 | 每星球总额度 | 资源倍率 |
| --- | ---: | ---: |
| 出生星 | 8 | 1 |
| 出生星系其他星球 | 6 | 3 |
| 其他星系 | 4 | 10 |

资源点先保留固定 10% 的通用原胚权重，其余 90% 按星球类型从目标星球当前实际资源中选择：

| 星球类型 | 矿脉 | 流体/气体 | 通用原胚 |
| --- | ---: | ---: | ---: |
| 火山、沙漠 | 80% | 10% | 10% |
| 海洋 | 55% | 35% | 10% |
| 冰原 | 60% | 30% | 10% |
| 气态巨星 | 0% | 90% | 10% |

- 矿脉使用 `veinGroups` 中仍有储量的 `MiningItem`。
- 固态星球的流体使用 `waterItemId`；气态巨星使用 `gasItems`。
- 选中类别后，在该星球此类实际资源中等概率选择具体物品。
- 某一实际资源类别为空时，其权重全部转给该星球其他实际资源类别，通用原胚仍保持 10%。
- 星球没有任何可读取的实际资源时，其余 90% 退回铁、铜、硅、钛、石、煤、原油、水、氢和重氢的通用候选表。

数量为：

`5 * 物品 StackSize * 区域倍率`

### 5.3 探测、HUD 与认领

信号名称直接使用全局稳定递增点位 ID：`FirstRelic` 和 `PlanetDetector` 显示为 `关键信号{ID}`，普通 `DirectionEligibility` 与 `ResourceCache` 统一显示为 `信号{ID}`。关键信号公开目标星球名称；普通信号在认领前不得公开恒星系、星球、内容、承载物品、坐标、方向或真实距离。

星球探测器使用目标星球中心距离 `Dplanet`。令：

- `DplanetMin = planet.realRadius + 900`。
- `DplanetMax` 为当前星团中任意两个恒星位置距离加两端星系半径之和的最大值；单星星团至少取该星系直径。星系半径按 `systemRadius * 40000` 转为游戏单位。
- 玩家 `planetId` 等于目标星球时，`Splanet = 1`；否则按下式计算并钳制到 `[0, 1]`：

`Splanet = log(DplanetMax / Dplanet) / log(DplanetMax / DplanetMin)`

因此进入目标星球局部范围后星球读数固定为 100%，不响应地表移动。

遗物探测器只在玩家 `planetId` 等于目标星球时计算，否则 `Srelic = 0`。令点位距离为 `Drelic`，认领距离为 `DrelicMin`，`DrelicMax = 2 * markRadius`：

`Srelic = log(DrelicMax / Drelic) / log(DrelicMax / DrelicMin)`

该值同样钳制到 `[0, 1]`。固态星球的 `DrelicMin` 为 120，气态巨星为 `max(120, realRadius * 0.25)`；点位半径分别为 `realRadius + 1.5` 与 `realRadius + max(40, realRadius * 0.25)`。

两个原始强度都按当前量化步长 `q` 向下取整为 `floor(S / q) * q`，原始 100% 保持 100%。步长与能力如下：

| 探索信号增幅等级 | 显示步长 | 附加能力 |
| ---: | ---: | --- |
| 0 | 20% | 遗物/星球探测器按各自解锁状态工作 |
| 1 | 10% | - |
| 2 | 5% | - |
| 3 | 2% | - |
| 4 | 1% | - |
| 5 | 0.5% | - |
| 6 | 0.5% | 主动位置标注 |

左侧 HUD 固定五个逻辑槽：第 1 槽显示当前关键信号且不可取消，第 2..5 槽保存普通信号 ID。新普通信号只填第一个空槽，满槽时不替换；取消固定只清空该槽，其他槽不移动。每名玩家的四个槽和已观察最大点位 ID 写入 UI 保存块，不进入文明快照。探索面板列出全部活动信号，并允许普通信号固定/取消固定。

六级的“标注位置”按钮只对当前选中信号调用原版 `UIGlobemap.SetLocationTracking(astroId, localPos, 519)`。原版入口先替换现有 `LOCATION_TRACKING` 标记，再建立目的地标记和指引线；FE 不调用 `Player.Order` 或 `PlayerNavigation.Navigate`。

点位永久存在；进入以点位为球心的认领范围后自动认领。研究点调用 `DiscoverContent(contentId, itemId)`，把该具体内容绑定到点位指定的承载物品；资源点调用允许超容量的 `AddExplorationReward`。

### 5.4 黑雾掉落

每次地面或太空黑雾击杀分别独立判定：

- Frag：基础 1%，探索信号增幅每级相对提高 20%，即 `1% * (1 + 0.2L)`，六级为 2.2%。
- 通用原胚：固定 1%，不受成长科技影响。

地面掉落使用原版地面敌人垃圾入口，太空掉落生成可拾取太空垃圾；生命周期均为 1800 tick。客户端不自行判定。

## 6. 亚空间与物流

### 6.1 库存与容量

库存为 `long[12000]` 数量与增产点数组。每种物品常规容量独立计算：

`capacity(item) = (10 + 10 * capacityLevel) * max(1, item.StackSize)`

亚空间扩容完成等级记为 `L`，范围 0..10000。容量从 10 组开始；第 1 至 8 级使用独立稳定节点，第 9 级节点以 `Level = 9, MaxLevel = 10000` 继续长期成长。满级为每种物品 100010 组。普通上传只接收剩余容量，探索奖励可使现有数量超过容量；超量期间普通上传剩余容量为 0，但下载始终可用。

存取保留并按实际件数拆分增产点。数量和增产点加法采用非负饱和，导入时把增产点钳制到每件最多 10 点。

### 6.2 访问入口

- 面板手动存取：通信建立后可用，不消耗机甲能量。
- 基础塔正面上传：整批容量预检，无额外能耗。
- 物流交互站：按槽位传输模式和阈值自动存取。
- 高级塔上传：按塔物品 ID、数量与增产点正常入库。
- 探索奖励：允许突破容量。

物流交互站保留 `Sync / Upload / Download` 传输模式与有限/无限容量模式。站点下载保留亚空间中的真实增产点，不自动补喷。

### 6.3 物流交互耗能

单件基础耗能：

`cost = sqrt(itemValue) * 10000 * InteractEnergyRatio * max(0.4, 1 - 0.1 * efficiencyLevel)`

本轮每槽预算为 `station.energy / storage.Length`，并再次限制为不超过当前站内电量。可搬运数量取目标差值与 `floor(budget / cost)` 的较小值。上传还受亚空间实际接收数量限制；未接收数量和对应增产点留在槽内。最终按实际搬运件数向上取整扣电。

亚空间存取能效共 6 级，每级降低 10%，最低倍率 0.4。

物流交互站制造配方分别使用对应原版物流运输站 1、基础矿物塔 4、基础解析塔 4。

- 每项缓存钳制到 400（20 堆 × 最高堆叠 20），增产点钳制到数量的 10 倍。
- 营养钳制到 0..1000，非有限值归零。
- 不存在或不是高级配方的 ID 归零。

### 9.2 旧档迁移

- `version == 12`：直接读取当前格式稳定块；早期同版本存档缺少可选 `DetectorState` 时按“星球探测器未恢复”处理，保留已有普通点位，并在首遗物已认领且曲速可用时补生第二个关键信号。缺少 `PinnedExplorationSignals` 时，HUD 首次观察活动普通信号后按 ID 填充空槽。
- `version == 11`：读取原稳定块；缺少 `ExploredContents` 时，把每个旧资格方向尚未解析的内容按稳定顺序绑定到一个承载物品；旧活动资格点按物品选择尚未占用的具体内容。旧独立科技状态迁移到同 ID 的 `Level/MaxLevel` 链，已经开始或完成的科技行标记为已解析。
- `version < 11`：不读取旧 FE 自有状态，标记为旧代际并显示不兼容提示。
- `version > 12`：不按当前格式向后猜读，显示不兼容提示。
- `version < 10`：`LegacyProtoMigration` 额外对原版持久容器中的 FE 2.x Item/Model/Recipe 物理引用做一次映射。
- `version == 10`：不执行 2.x 物理迁移，也不解释为当前格式状态。
- 下次保存写入版本 12，因此版本 11 状态迁移和更早物理迁移都不会重复。

四个旧塔物理 ID 映射到基础矿物、基础解析、高级交互和高级转化；高级矿物使用新物理 ID。物流交互站及可对应原型继续解析。旧协议、成就、科技点、塔等级和旧自有库存语义不迁移。

### 9.3 蓝图与复制粘贴

高级塔选定配方使用参数头：

- Magic：`0x46524543`。
- Version：`1`。
- Payload：稳定整数配方 ID。

复制建筑设置、粘贴、蓝图生成、预建筑实体化和强制覆盖路径均使用同一参数。应用前验证实体确为高级塔、配方存在、塔型匹配且已研究；非法值拒绝或归零。缓存和营养不进入蓝图。

### 9.4 Nebula

主机每秒广播高级塔完整状态；研究、探索或亚空间库存变脏时，脏状态在主线程合并，文明快照最多每秒广播一次。玩家中途加入时，主机补发两类快照。

文明快照包含：

- `Civilization`：具体内容探索映射、共享解析槽、科技发现状态、探测器状态和探索点内容。
- `Recipes`：配方统计。
- `DataCenter`：完整稀疏亚空间库存。
- `Process`：过程统计。
- 配置堆叠值，以及保留兼容字段的 Frag/Memory 绝对余额。

`CivilizationActionPacket` 只允许 `ClaimExploration = 1` 和 `markId`。主机从连接对应的 `IPlayerData.UPosition` 读取三维宇宙坐标，并按目标星球类型和点位球形范围验证距离；客户端不提交坐标。HUD 普通信号固定槽不随该快照发送，各玩家只能改变自己的 UI 偏好。

`BuildingChangePacket.packetType = 2` 表示高级配方选择，`itemId` 字段承载稳定整数配方 ID。主机只有在实体、塔型、研究和配方校验通过后才向其他客户端传播。

## 10. 兼容与边界

- `GenesisBook`：调整 FE 科技位置和快速开局过滤；过滤范围必须覆盖 2061..2062、2081..2085、2091..2099 及五条六级成长行。
- `OrbitalRing`：调整科技位置并保留教程动态布局兼容。
- `Nebula`：所有参与者版本字符串必须一致。
- `TheyComeFromVoid` 等第三方兼容继续由 `Compatibility/Mods` 单文件所有者维护，不得把外部状态写成 FE 研究真源。
- 内部类名 `DataCenter*` 和旧科技常量 `TFE分馏数据中心` 是稳定兼容实现；2051 不注册 Proto，玩家可见名称使用“分馏亚空间”。
- 旧货币包裹 ID 仅可用于导入时折算误入库存的历史数据，不注册为正式物品或入口。

## 11. 设计红线

生产实现和后续改动必须满足以下可检查约束：

- 活动塔目录长度恒为 5；不得注册高级解析塔或旧四塔的额外原型。
- 五塔每类缓存只能是 `20 × 当前全局堆叠` 件，不得另设独立的缓存成长。
- 原版分馏塔在任一全局堆叠下都不得因输出限流而堵塞满带产线。
- 基础失败物和高级失败普通输入不得损毁；输出堵塞不得丢物。
- 高级塔运行必须满足已选合法配方、反应物齐全和输出空间足够；营养为 0 时按当前耐久比例降速，不得硬停机。
- 高级塔不得接入电网作为运行成本，不得由原版维修恢复营养耐久。
- 未探索的具体内容不得进入解析候选；一次探索不得把整个物品池或同一内容的全部关联物品同时开放。
- 科技方向未解析时不得显示或排队；解析后必须整行显示，但首级外部条件不得绘制跨行或跨页连线。
- 2061/2062 必须显示在第一页；第二页只承载成长科技。
- 未认领普通信号不得泄露恒星系、星球、具体内容、承载物品、坐标、方向或真实距离；只有关键信号可公开目标星球。
- FE 不得启动自动导航、创建 `OrderNode`、写入 `navigation.navigating` 或改变机甲运动状态；只允许精确识别并终止旧版本遗留的首遗物导航。
- 主动位置标注只能由玩家点击触发，并且只能调用不含移动命令的原版位置标注路径。
- 星球探测器在目标星球局部范围内必须固定为 100%，遗物探测器在目标星球之外必须固定为 0%。
- 普通模式未完成探索解析的 FE 科技不得因显现补丁开放；沙盒一键解锁按原版 `Published` 资格直接解锁并显现有限科技，长期成长节点不得被批量升满。
- 探索奖励可以超容量，其他上传不得借此绕过容量。
- 塔特质研究和高级塔献祭不得在同一次塔投入中同时结算。
- 配方、存档、蓝图和联机必须使用稳定 ID；类名和显示名称不得成为身份。
- 客户端不得独立结算研究、探索、反应或耐久。
- 旧协议、成就、远古科技点、定向原胚、黑雾样本、主路锁定和副产物弃置不得重新进入正式路径。
