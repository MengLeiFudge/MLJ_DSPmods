# Fractionate Everything 已废弃设计

本文记录曾经评估或实现、后来被否决的设计方向，以及否决原因，用于避免重复讨论同一方向。本文不是设计真源，任何条目都不约束当前实现；当前设计以 `GAME_DESIGN.md` 与 `GAME_DESIGN_SPEC.md` 为准。

条目只写方向、否决原因和替代方向。替代方向的具体规则以设计真源为准，本文不重复数值。

## 1. 引导与探索

### 四挡探测器

- 方向：探测器分四个精度挡位，以 Alt+R / Alt+T 切换，显示经纬度区间和精细百分比，引导玩家逐挡缩小范围。
- 否决原因：经纬度区间和精细百分比是当时按需求提供的，后来确定探索感优先：读数比对和切挡操作把找点变成按坐标执行，方位词与“请切换挡位”式提示等于直接教玩家怎么玩。
- 替代方向：首条主线只给图形强度条；后续主线用原版导航与地表标记；非主线在接近前完全隐藏，首次进入范围后永久记录。

### 塔窗口内的详细动作提示

- 方向：在高级塔窗口里逐步提示下一步操作。
- 否决原因：窗口只应反映状态；教学写进窗口会显得把玩家当作不会操作。
- 替代方向：窗口只保留状态标记，教学放进手册、前人开发案和日志等世界观载体。

### 提供接线蓝图

- 方向：为混带高级塔提供标准接线蓝图。
- 否决原因：混带接线本身就是解谜挑战，“难操作换高收益”是 FE 的核心取舍。
- 替代方向：混带规则保持不变，不提供接线答案。

### 首遗物授予步行升级链

- 方向：首次回收遗物时自动解锁机械骨骼步行科技。
- 否决原因：这是与生命工业无关的附赠奖励，并且会越过原版科技进度。
- 替代方向：删除这项授予。

## 2. 跨存档成长

### “是否玩过”档案与老玩家提前堆叠路线

- 方向：本地记录“已完整体验生命工业”，新存档可走更早开放堆叠的路线，并额外发放物流补给。
- 否决原因：这是二元资格，不能体现玩过的程度，还和堆叠科技链形成两套路线。
- 替代方向：删除该资格与补给，统一记录通关次数，跨存档影响改由其他存档的宇宙矩阵峰值提供。

### 跨存档加成取对数

- 方向：用 log10 或 ln 压缩其他存档数据，避免多次游玩带来过大的加成。
- 否决原因：实际游玩次数很少超过十次，对数让前几份存档的贡献过低；不需要为不会发生的极端次数压缩曲线。
- 替代方向：按其他存档宇宙矩阵峰值之和线性加成。

### 元数据共用原版余额并扣账

- 方向：FE 直接消耗原版元数据余额，与原版买断功能共用同一笔数值。
- 否决原因：会与原版元数据用途互相挤占，FE 也无法单独定义自己的语义。
- 替代方向：只读原版峰值记录，另记 FE 专属额度。

## 3. 价值与存储

### 存储价值与全局价值双轨

- 方向：亚空间存储使用一套价值，配方与估值使用另一套。
- 否决原因：两套价值会让同一物品出现两个“价格”，难以理解，也难以维护。
- 替代方向：只保留一套全局价值；原先依赖特殊价值上限做排除的逻辑改按物品类别或显式名单判断。

### 溢出价值兑换实体

- 方向：自动上传超出容量的部分折算为溢出价值，之后可兑换回实体物品。
- 否决原因：可回兑的溢出价值就是第二套货币，违背单一价值原则。
- 替代方向：溢出价值只作为沉没进度用于扩容，与消耗矩阵扩容同理，消耗后不可退回。

## 4. 高级塔

### 矩阵进入转化塔配方

- 方向：把矩阵作为转化塔配方的输入，并保留矩阵互转链。
- 否决原因：所有高级塔都以矩阵为食物，矩阵再进配方会让同一物品承担两种角色。
- 替代方向：除分馏丰碑专用配方和已确认恢复的黑雾材料相邻转化外，矩阵只作食物；配方的操作深度来自多输入组合和分档消耗比例，矩阵互转链删除。

### 仅 6001～6006 可作食物

- 方向：按连续物品 ID 判定高级塔食物。
- 否决原因：兼容模组新增的矩阵以及黑雾矩阵无法进入判定，而黑雾矩阵在世界观上应当可以被处理。
- 替代方向：物品类型为矩阵，或物品为黑雾矩阵时即可作为食物。

## 5. 分馏丰碑

### 丰碑直接推进科研

- 方向：丰碑能量用于加速科研，或让无限科技每级耗时保持恒定。
- 否决原因：后期无限科技的收益是零散的小幅数值叠加，不改变玩家实际在做的事，不足以支撑终局巨构。
- 替代方向：丰碑作用于原版配方的生产速度。

### 产量、元数据、丰碑的自增殖循环

- 方向：丰碑提高产量，产量提高元数据峰值，元数据再继续推高丰碑。
- 否决原因：闭环可以单靠挂机自行增长，玩家没有新的建设决策。
- 替代方向：不把这条闭环当作成长主线。产能新高推高元数据、进而提升丰碑等级的反馈仍然存在，但元数据只记峰值：生产指标必须创出新高才授予额度，恒定产能不重复授予，挂机本身不增长；持续成长由接收站专属材料逐批解析提供。

### 丰碑继续提高实际堆叠

- 方向：丰碑同时提高实际货物堆叠并缩短配方时间，制造速度增长快于堆叠增长，使单条满带的吞吐增加，同时减少填满一条带所需的机器数。
- 否决原因：原版货物数量和每堆总增产点均用 `byte` 保存，最大值为255；兼容每件10点增产时，一堆最多只能完整保存25件的增产点。突破该表示需要联动调整货物结构、传送带、分拣器与建筑交接接口、存档、联机和GPU数据布局，无法只提高FE的层数上限，改动及跨模组兼容成本过高。
- 替代方向：实际堆叠上限保持20层，丰碑继续缩短普通已注册配方的制造时间。该取舍可减少满带模块所需机器数，但不提高传送带自身的满带吞吐；具体规则以 `GAME_DESIGN.md` 与 `GAME_DESIGN_SPEC.md` 为准。

### 一个矩阵当多个用作为核心收益

- 方向：降低每件矩阵对应的科研点数需求，使同量矩阵完成更多科技。
- 否决原因：实现干净，但只节省矩阵，而后期矩阵通常不是瓶颈，收益有限。
- 替代方向：不作为丰碑核心收益。

### 以高级塔产出量倍率代替配方时间

- 方向：丰碑提高 FE 高级塔每次成功的产物数量，而不是缩短配方时间。
- 否决原因：丰碑的目标是原版配方，原版配方本来就有可调整的配方时间。
- 替代方向：直接缩短原版配方时间。

### 原版配方时间的人为下限

- 方向：为缩短后的原版配方时间设置软下限或固定下限，避免供料跟不上。
- 否决原因：引擎已将配方时间限制为至少 1 帧；供料能否跟上是玩家的工程问题。
- 替代方向：不另设下限，所有原版配方压到 1 帧即为丰碑终局。

### 丰碑发射替代方案

- 方向：删除丰碑发射动画，或自建发射组件，或让组件直接入库。
- 否决原因：需要兼容原版、星环和巨构对电磁弹射器与发射井的既有改动；另起一套发射逻辑会与这些改动冲突。
- 替代方向：不改发射逻辑，为电磁弹射器（含星环重型弹射器）和火箭发射井分别提供丰碑专用弹药。

### 丰碑只能建在红巨星或蓝巨星

- 方向：丰碑只允许建在特定巨星所在星系。
- 否决原因：部分星图没有对应巨星，玩家会无法完成终局。
- 替代方向：任意星系都可建造，按红巨星、蓝巨星、其他恒星的顺序加权。
