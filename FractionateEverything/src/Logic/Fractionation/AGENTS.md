# Logic/Fractionation — 五塔与配方域

本域拥有五座分馏塔、基础/高级运行路径、稳定配方目录、实例持久化、蓝图配方选择和分馏塔窗口表现。

## Structure

```

│   ├── Definitions/                 # 两座基础塔、三座高级塔原型
│   ├── FractionatorTowerCatalog.cs  # 五塔稳定目录与 ERecipe 映射
│   ├── FractionatorRuntime.cs       # 基础塔单输入、输出、正面上传与共享参数
│   ├── VanillaFractionatorOutput.cs # 原版塔流动物和产物补放

│   ├── FractionatorBlueprintParameters.cs # 共用蓝图状态块读写
│   ├── AdvancedFractionatorRuntime.cs # 多输入/输出、食物、营养、耐久、状态

│   ├── AdvancedRecipeSelectionSync.cs # 复制粘贴、蓝图和联机配方 ID
```

## Stable Identities

- 活动塔目录固定为基础矿物、基础解析、高级矿物、高级交互、高级转化，共 5 项。
- `ERecipe` 数值保持：高级交互 1、基础解析 2、基础矿物 3、高级转化 4、高级矿物 5。
- 物理 Item/Model/Recipe ID、`WorldviewRecipe.StableId` / `PersistentId`、蓝图 magic/version 和存档块名不得因源码重命名改变。
- 旧中文塔常量只能作为同 ID 兼容别名，不能注册旧塔或建立第二套目录。

## Runtime Rules

- 基础塔输入使用 `ProcessManager.BufferCapacity`（20×当前全局堆叠件），高级主料使用40×当前全局堆叠件；货物计数参与速度，不替代这两条准入策略。
- FE塔的产物与流动输出阈值读取 `ProcessManager.OutputCapacity`（5×当前FE堆叠件）；原版塔在六层接管前保持20件，之后使用相同阈值。按本批开始前数量准入，整批结果允许越过阈值；禁止以最坏产量预留空间或按单轮产量扩大阈值。
- 原版分馏塔输入缓存保持 `FractionatorManager.VanillaFluidInputCargoMax`（40）货物堆；六层研究完成后由 `ProcessManager.TopUpVanillaOutputs` 把流动输出和产物叠到输出带头部。已放置塔的原版缓存字段由 `FractionatorManager.SetFractionatorCacheSize` 与 `FactorySystem.Import` 补丁同步。
- 基础塔按带尾真实stack做整批准入；基础矿物失败回流，解析按研究域的价值概率区分成功、损毁和流回，具体公式见GAME_DESIGN_SPEC。
- 高级塔先验证已研究且塔型匹配的稳定配方 ID，再接收多输入和矩阵食物。
- 主料与辅料使用40×当前集装层数件准入阈值；消耗概率低于10%的催化剂至少保留5件或一轮需求。备用食物硬容量等于当前全局堆叠层数；存档与快照按绝对层数上限校验，已有合法备用不因研究状态尚未恢复或层数降低而丢弃，消化物与备用同种，二者均空才可切换。配方矩阵优先作为反应物，仅空腹且无备用时先取一件点火。当前格式保存消化剩余比例；不读取旧消化格式或转换异种备用。
- 旧/无关物优先排出；产物达到阈值时停止反应，将现有及新到普通输入改走流动输出，保留数量、增产点和真实货物计数。高级塔全部流动物与产物等待当前全局满堆，缺料、缺催化剂及堵塞均不拆堆，旧料不足一堆时保留供手动取出；多个产物按实际积压轮转。流出达到阈值且已连接流出口时，全塔只允许借用一次额外整堆收料空间来解除满带回环等待，成功流出一堆才归还；CirculationIntakePending独立命名保存，换配方不清除，新增块不改version10。
- 高级主料按自身真实货物与堆叠独立推进件数进度；主料及待排空输入共享侧面输入带总速率（不超过MaxBeltSpeed），按真实货物需求分摊，禁止每物品独占整带能力。流动输出两侧共用同一货物发送额度，最多积攒一堆，堵塞后不补发时间欠账；无输入带时按单带能力处理手工库存。配对完整轮统一反应，多余已推进主料保留增产点回流；保留一轮配对储备与小数，缺其他主料或催化剂仍可循环。进度不得超过实物，堵塞不新增进度，手动取物同步扣进度但不计运行流量。
- 高级结算采用 `floor(expected + U)` 的批量期望取整；基础成功率乘以共享Memory分钟献祭加成。可执行轮数由各主料独立进度与实物配对得到；扣任何主料前，用所有辅料实际库存与特质后的消耗概率限制成功数，再统一结算回流、产物和营养，不以截断扣料掩盖欠账。
- 高级塔由当前消化矩阵提供速度与能量，不耗电；`MatrixNutrition` 根据统一价值建立食物目录，接纳 Matrix 类型及黑雾矩阵5201。成功轮按真实主料件数耗能，待机仍耗能，断粮按耐久降速并损坏。具体公式见GAME_DESIGN_SPEC第3章。不使用 `hpIncoming`，原版维修不能恢复生命塔。
- 基础解析配方为显式研究样本、Memory、Frag、高级塔和六种主线矩阵建立；矩阵先转入DataCenter的扩容供料，未接收部分带原增产点回流，不再同时进入样本研究。塔体有已探索配方/特质时先解析，无候选且献祭已开放时才以2%成功率产出Memory。培育用原胚，繁育用对应塔体，不通过输入输出推测样本。
- 主动拆除返还所有真实字典缓存；损毁只移除状态。原版单槽镜像只供显示，不能用来返还。

## State And UI

- `AdvancedFractionatorRuntime` 是高级塔缓存、营养和选定配方的唯一真源；原版字段只镜像当前配方第一输入/第一产物。
- 导入将外部字节视为不可信，限制状态数、字典项、ID、数量、营养和增产点。
- 蓝图/复制粘贴只保存选定配方 ID，不复制缓存或营养。
- 基础塔与高级塔窗口共用固定几何；配方左上、配方名称和图标中心对齐右上两行状态中心的均值，食物在输入与流出第一排之间，三标题同排；高级塔右上沿用原版相对右上角位置，两行分别显示食物供养状态与配方处理状态，区分流动输出堵塞和产物输出堵塞；食物槽下显示消耗速率与当前一件剩余百分比，输入与流出各2×2同序网格，下方4格产物。每格复用原版圈、右下数量与悬停；主料显示实际独立经过速率（配对参与及未配对回流），不由共同轮数推算；显示层保留4个半秒样本做约2秒滑动平均，每半秒刷新，零样本不清空历史，比例使用同一平滑值，切塔/物品/配方立即重置；占比以一条当前满堆叠带按配方平均消耗分摊的速率为100%，食物不计入。辅料、催化剂与产物以实际配对轮速率估算；催化剂也显示混带分摊占比，食物及辅料低速保留两位有效数字，1～10一位小数、10及以上截取整数部分，流出只显示数量。产物仅显示库存或刚产出项，按配方顺序补位；未用槽保留空圈。删除总速率、累计统计、比例及每格规则长文，禁止恢复主路锁定、副产物弃置和详细接线提示。
- 表现代码不得直接写研究状态；选择操作统一走 `AdvancedRecipeSelectionSync`。
