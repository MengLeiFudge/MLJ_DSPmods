# Fractionate Everything 游戏设计

本文是 FE 当前游戏设计与机制契约的事实源，面向作者和 AI 维护者。它只记录稳定目标、玩家决策、系统关系、机制不变量和设计红线；公式、概率、阈值、状态字段、代码入口和 UI 操作规格见 `GAME_DESIGN_SPEC.md`。

两份文档使用相同章节顺序。规格只能细化本文件，不能改变本文件定义的系统目的和边界。候选方案、未确认平衡、实现差距、审计过程、提交记录和构建发布状态不进入正式设计文档。

## 1. 模组定位与体验目标

FE 的核心是把原版重氢分馏的单输入概率加工模型扩展到更多物品，并以远古文明协议恢复组织这些配方。

- 主线服务原版游戏流程，只加快和重构生产，不跳过关键材料、能源和探索阶段；建筑转化可以用大量低层建筑提前换取下一层建筑。
- 玩家通过建设真实产线取得残片与记忆源点、恢复协议并重建远古科技，而不是通过 UI 直接领取生产成果。
- 玩家最终可以在单存档中恢复全部核心协议和科技方向；随机性只改变发现顺序和恢复节奏。
- 概率结果必须能被自动化规模吸收，不能依赖限时、每日次数、付费式卡池或长期重复抽取。
- 远古文明只留下可恢复的档案、协议和设施能力；关键材料仍需满足原版科技、资源和生产条件，建筑升级链不要求先解锁或制造目标建筑。

FE 的目标体验是一条"发现设施—生产残片—检索协议—支付解锁—建设新产线—深层解析—恢复设施能力"的持续闭环。每次恢复都应增加可规划的生产选择，而不是增加一套脱离工厂的独立小游戏。

## 2. 核心玩法循环

核心循环按以下关系推进：

1. 玩家取得通用原胚，重建第一批培养塔和解析塔。
2. 解析塔把矩阵和样本转化为残片实体，残片生产按固定比例派生记忆源点；玩家把实体上传数据中心入账。
3. 玩家选择广域、方向或锚定策略检索协议；每次检索都消耗残片。
4. 协议完整度达到 100% 只取得购买资格；玩家用记忆源点和实物支付，由主机原子结算后正式解锁协议，建设真实分馏产线。
5. 全局协议目录不再有未完成候选后，广域检索转为深层解析并产生远古文明科技点。
6. 玩家在四条塔型科技主干中选择恢复顺序，逐步开放堆叠、持续运行和实例控制能力。
7. 普通成就记录当前存档里程碑；秘密成就记录本机 profile 纪念内容。

该循环必须满足以下契约：

- 解析、检索、解锁、生产和科技恢复各有独立职责，不能由单一 UI 按钮直接跨越多个环节。
- 已取得的协议完整度永久保留；失败只影响当前检索收益，不回退既有进度。
- 自动化规模提高残片获取和协议实践速度，但不能制造永久不可得内容。
- 玩家任何时候都应能说明下一步缺的是残片、记忆源点、协议完整度、实物支付还是科技点。

## 3. 资源与状态体系

文明恢复使用职责不可互换的货币：

- 残片 Frag：普通检索货币，每次检索都消耗残片。
- 记忆源点 Memory：正式解锁货币，由残片生产按固定比例派生，用于购买达到 100% 的协议。
- 远古文明科技点：永久科技资源，只用于购买远古科技树节点。

残片和记忆源点既有数据中心余额，也有面额实体形式：解析塔把矩阵和样本转化为残片实体，记忆源点由残片生产派生为实体；实体上传数据中心按面额入账。余额只可下载为基础面额实体；包裹面额实体只由解析塔输出且只可上传。三种货币互不可兑换。

稳定状态分为五层：

- 货币状态：残片余额、记忆源点余额、残片生产尾数和深层解析进度。
- 协议状态：是否发现、完整度和是否正式解锁。
- 配方状态：累计实际产出成功次数，用于校准运行控制。
- 科技状态：科技点、科技节点和恢复进度。
- 成就状态：普通成就按存档保存；秘密成就按本机 profile 保存。

定义目录不进入存档；玩家状态进入存档；运行缓存由稳定状态投影生成。任何系统都不得把同一事实同时保存在多个权威状态中。

## 4. 文明解析与协议检索

数据中心内的残缺 AI 是文明档案管理核心，只负责维护索引、校验权限和调度设施。它不能读取协议正文，不能自行创造科技，也不能绕过玩家产线生成残片、记忆源点或科技点。

解析塔把矩阵和样本转化为残片实体，残片生产按固定比例派生记忆源点；上传把实体计入数据中心余额，作为检索与解锁的支付来源。

协议检索提供三种玩家决策：

- 广域检索：在全局目录全部可行动协议中随机结算。
- 方向检索：把候选限制到指定配方方向，但仍保留方向内随机性。
- 锚定检索：固定一个未完成协议，并保证该协议被发现或推进。

每次检索都消耗残片；残片成本随全局已执行的检索次数增长，并有上限。成本增长必须服务节奏控制，不能让后期协议在有限游戏时间内事实上不可恢复。方向与锚定检索在基础成本上按比例加价。

检索必须遵守以下机制契约：

- 没有可行动协议且不可执行深层解析时，不消耗残片。
- 普通检索允许无效响应，但无效响应必须返还部分残片成本，并受到保底约束。
- 锚定检索不能消耗残片后只产生无效响应或无关协议结果。
- 批量检索必须严格等价于按相同顺序逐次执行单次检索，每一步都更新候选池、残片余额、保底和完整度。
- 候选池由全局目录中具备资格的未完成协议构成，同塔同输入只存在一张协议。
- 全局目录没有未完成候选时，广域检索执行深层解析并累计科技点进度；方向或锚定检索在指定方向或目标无候选时不可执行，不消耗残片。

## 5. 协议目录与配方

协议是旧文明留下的生产规则，不是可反复升级的卡牌。协议首次发现后永久保存进度；完整度达到 100% 只取得购买资格，正式解锁需要支付记忆源点和实物，解锁后对应配方才能运行。

协议目录是全局唯一的：每张协议由塔型与输入物品共同标识，同塔同输入只存在一张协议；目录不再按矩阵阶段分段。

进入随机协议目录的内容仅包括：

- 可持续消耗原矿的资源复制配方。
- 同一工业链或用途链中的便利性转化配方。
- 满足培养资格后的实体塔返祖配方。

以下内容属于基础设施，不进入随机协议池：

- 通用原胚随机培养。
- 专属原胚稳定培养。
- 矩阵与样本的残片生产。
- 通用原胚谱系分化。

协议进入候选池的资格：普通物品协议不设额外解锁前置，正式解锁所需的实物支付天然限制超前恢复；黑雾物品协议只有在玩家实际接触对应掉落后才进入候选池；实体塔返祖协议在对应专属培养达到资格后才进入候选池。特殊协议的前置由协议显式定义。黑雾路线是可选的调查支线，只加速恢复节奏，不阻塞任何完成条件；战斗本身不发放残片、记忆源点或科技点。

复制塔以同种资源复制为主产物，并保留既定的自然伴生副产物；它不复制临界光子、反物质或其他承担关键原版系统边界的产物。转化塔只提供已经确认的建筑、设备、燃料、防御、弹药、消耗品和黑雾物品链转换，不能发展成普通材料间的万能等价交换。建筑升级链允许投入大量低层建筑取得下一层建筑，不要求先解锁或制造目标建筑。

正式解锁按协议族确定实物需求：复制协议只收输入；普通材料协议收输入与全部输出去重；建筑升级协议通常只收输入；特殊协议的支付由协议显式定义。不同物品各消耗一组实物。当前存档首个协议首次达到 100% 时会立即获得一次性记忆源点奖励，不等待正式解锁。

配方变体、新供应链和打包物只在基础配方分类稳定后逐族评估，不能为了内容数量批量复制一套镜像物品或配方。

## 6. 四塔职责与原胚体系

四类塔与四类配方职责固定：

- 培养塔：培养原胚、执行实体塔返祖、上传物品并连接数据中心。
- 解析塔：把矩阵和样本转化为残片实体并派生记忆源点，把通用原胚分化为专属谱系。
- 复制塔：复制可持续消耗的原矿资源，并保留配方既定的自然伴生副产物。
- 转化塔：执行已确认物品链中的层级转换，允许大量低层建筑转化为下一层建筑。

塔型和输入物品共同唯一确定配方，也共同唯一确定协议。不能因为某类配方数量较多，就按数量机械拆出更多塔型。

原胚系统遵守以下契约：

- 通用原胚主要来自开采装饰物、异常信号和探索事件等非自动化入口。
- 通用原胚可随机培养为四类实体塔；专属原胚只稳定培养对应塔。
- 解析塔可以把通用原胚分化为四种专属谱系；取得主路锁定许可并完成配方校准后，玩家可以指定谱系。
- 实体塔返祖只产生对应专属原胚；返祖协议必须在对应专属培养达到资格后才进入检索池。
- 返祖协议是后期可选附属内容，不阻塞任何完成条件。

开局必须提供足够多的通用原胚，确保随机结果不会阻断第二座培养塔和首座解析塔。遗迹只要求玩家手动重建培养塔，其他建筑保持可观察的完整运转结构。首轮教学必须让玩家看到"培养第二座培养塔，再把第一座塔的正面产物接入第二座塔正面完成上传"的完整闭环。

## 7. 远古科技与运行控制

科技树只消耗远古文明科技点，科技点只由无候选广域检索的深层解析产生。四条稳定主干按培养塔、解析塔、复制塔和转化塔排序；每条主干恢复同一组塔型通用能力，玩家在前中期选择优先方向，当前存档最终可以取得全部主干。

主干能力按以下顺序形成清晰的运行成长：

- 流动输出堆叠。
- 产物输出堆叠。
- 产物缓存满载时继续分馏。
- 主路锁定。
- 副产物弃置。

五项能力彼此独立，但每一项都必须以同一结构覆盖四类塔：四塔都拥有该能力的授权状态和 UI，当前值可以不同；不能因为某塔或当前配方暂时无法获益，就从实现或界面中省略整项能力。前两项和持续分馏在对应塔型科技恢复后自动生效。主路锁定与副产物弃置必须同时满足三层许可：对应塔型科技已恢复、当前配方累计实际产出成功完成校准、当前实体塔保存了具体设置。

运行控制遵守以下边界：

- 同一项能力跨四塔复用同一份控制代码；配方只提供候选产物和结算算法，不决定该能力是否存在。
- 当前配方没有可选主产物或副产物时，主路锁定或副产物弃置显示当前无效果，不隐藏能力状态。
- 主路锁定只从主产物集合选择目标，不改变副产物。
- 副产物弃置只销毁副产物，不补偿主产物、成功率、输入、增产点、速度或其他收益。
- 配方校准只累计实际产生至少一个产物的成功；判定成功但产物数为零的批次不能提前推进校准。
- 实例设置必须随存档、复制粘贴、蓝图和联机同步。
- 文明与成就业务不能进入逐物品分馏热路径；热路径只读取各自状态生成的运行缓存。

主干承载塔型共享能力和核心特质；模组兼容、配方族和配方变体放在主干外分叉。分支节点可以要求基础协议、完成条件、原版科技或生产条件，但不能创建第二套不可回收科技货币，也不能让玩家永久失去其他方向。

## 8. 成就与长期目标

成就不消耗科技点，也不替代协议和科技树。成就分两类：

- 普通成就：当前存档内的固定生产里程碑，条件由真实生产、协议恢复、科技投入和分馏次数自然推动；完成后自动生效，可以定向增强配方族或提供轻量全局加成；奖励必须与完成时机匹配，不能让新档继承决定性生产强度。
- 秘密成就：按本机 profile 记录，只承载发现记录、背景或纪念内容，不发放生产强度或经济资源。

成就和科技节点彼此独立；任务式目标不应被强行挂到科技树上。成就定义和排序应服务玩家理解当前进度，而不是按代码模块机械分组。跨存档内容若未来存在，只能承担发现记录、背景、外观或不改变核心产线结果的便利功能，并需另行确认设计边界。

## 9. UI、教学与信息反馈

主面板长期保留生产、文明解析、资源、恢复指引、图鉴和设置等可持续使用的页面；一次性流程不得挤占长期分类。文明解析分类提供三个长期入口：

- 文明总览：展示残片与记忆源点余额、协议目录发现和完成情况、深层解析进度。
- 协议恢复：选择检索策略、方向、锚定目标、批量次数，并反馈每次结算、无效返还和保底。
- 远古科技树：展示科技点、四条塔型主干、前置条件和已恢复能力。

恢复指引分类提供恢复手册和成就。成就页面分别展示当前存档的普通里程碑与本机 profile 的秘密纪念；页面位置不改变成就与协议、科技树彼此独立的领域边界。

UI 只负责展示、选择和确认。它可以提交文明动作，但不能绕过业务规则直接生成残片、记忆源点、写入完整度、执行解锁或修改分馏结果。

检索与解锁必须向玩家反馈以下状态：余额不足、资格未满、特殊前置不足、原子解锁成功、旧档纪念；UI 不能把这些状态合并成无法诊断的单一提示。

教学必须优先解释玩家当前闭环和下一步缺口，不在界面中堆叠实现说明。恢复手册负责长期可查的系统说明；首次入口提示只负责把玩家引向对应页面。

旧抽取、成长商店、市场交易和旧线性配方成长已经移除，不得再注册旧页面、旧存档块或兼容迁移入口。

## 10. 存档、联机与版本迁移

文明定义、成就定义、配方定义和科技定义不进入存档。货币、协议、科技和恢复进度属于文明状态；普通成就完成记录属于存档级成就状态，秘密成就记录属于本机 profile；配方校准属于分馏状态。各状态分别持久化，运行缓存只在初始化和导入后重建。

存档版本采用硬切：总版本为 10；低于 10 的存档不读取任何 FE 自有状态块。识别为 FE 2.x 旧版（版本 1）的存档只触发"旧日余响"纪念内容，不发放任何奖励。

物理 Proto 兼容单独说明：FE 3.x 保持建筑、模型和物品的物理 ID 兼容（或提供映射），使旧蓝图和存档引用仍可解析；该兼容不依赖也不构成状态迁移。

联机采用主机权威模型：

- 客户端只能提交受约束的动作请求。
- 主机验证请求、结算资源（含正式解锁的原子扣减）、推进进度，然后广播完整权威状态。
- 客户端不能发送全量文明快照覆盖主机。
- 自动上传、普通成就完成和玩家加入等会改变或需要补发权威状态的节点由主机广播；秘密成就属于本机 profile，不进入存档与联机快照。

实例运行设置必须和文明状态采用一致的权威边界，不能出现客户端先行结算后再尝试覆盖主机的路径。

版本迁移必须幂等。没有真实旧存档和蓝图样本时，只能声明结构验证和人工映射复核，不能声明实档迁移通过。

## 11. 全局红线

- 不跳过原版关键阶段。
- 不让随机性决定核心内容是否永久可得。
- 不让自动化规模无限放大一次性抽奖价值。
- 不让 UI、任务、成就或商店替代真实产线。
- 不让残片、记忆源点和远古文明科技点互相兑换。
- 不让资源复制替代戴森球、射线接收、质能转换或其他关键原版生产边界。
