# Fractionate Everything 游戏设计

本文是 FE 当前游戏设计与机制契约的事实源，面向作者和 AI 维护者。它只记录稳定目标、玩家决策、系统关系、机制不变量和设计红线；公式、概率、阈值、状态字段、代码入口和 UI 操作规格见 `GAME_DESIGN_SPEC.md`。

两份文档使用相同章节顺序。规格只能细化本文件，不能改变本文件定义的系统目的和边界。候选方案、未确认平衡、实现差距、审计过程、提交记录和构建发布状态不进入正式设计文档。

## 1. 模组定位与体验目标

FE 的核心是把原版重氢分馏的单输入概率加工模型扩展到更多物品，并以远古文明科技探索组织这些配方。

- 主线服务原版游戏流程，只加快和重构生产，不跳过原版关键阶段。
- 玩家通过建设真实产线取得解析数据、恢复协议并重建远古科技，而不是通过 UI 直接领取生产成果。
- 玩家最终可以在单存档中恢复全部核心协议和科技方向；随机性只改变发现顺序和恢复节奏。
- 概率结果必须能被自动化规模吸收，不能依赖限时、每日次数、付费式卡池或长期重复抽取。
- 远古文明只留下可恢复的档案、协议和设施能力；玩家仍需满足原版科技、资源和生产条件。

FE 的目标体验是一条“发现设施—生产解析数据—检索协议—建设新产线—深层解析—恢复设施能力”的持续闭环。每次恢复都应增加可规划的生产选择，而不是增加一套脱离工厂的独立小游戏。

## 2. 核心玩法循环

核心循环按以下关系推进：

1. 玩家取得通用原胚，重建第一批交互塔和解析塔。
2. 解析塔将当前阶段矩阵转化为实体解析数据，交互设施把解析数据上传至数据中心。
3. 上传积累协议检索机会；玩家选择广域、方向或锚定检索，发现协议并永久推进完整度。
4. 完整协议开放对应资源复制、工业转化或实体塔返祖配方，玩家建设真实分馏产线。
5. 阶段主协议全部完成后，后续机会进入深层解析并产生远古文明科技点。
6. 玩家在四条塔型科技主干中选择恢复顺序，逐步开放堆叠、持续运行和实例控制能力。
7. 当前存档成就记录自然生产里程碑，并提供与完成时机相称的固定加成。

该循环必须满足以下契约：

- 解析、检索、协议、生产和科技恢复各有独立职责，不能由单一 UI 按钮直接跨越多个环节。
- 已取得的协议完整度永久保留；失败只影响当前机会收益，不回退既有进度。
- 自动化规模提高机会获取和协议实践速度，但不能制造永久不可得内容。
- 玩家任何时候都应能说明下一步缺的是解析数据、检索货币、协议完整度、配方校准还是科技点。

## 3. 资源与状态体系

文明恢复使用三类不可互换的资源：

- 残片：普通检索货币，用于收窄方向。
- 记忆源点：稀缺检索货币，用于保证锚定目标得到有效推进。
- 远古文明科技点：永久科技资源，只用于购买远古科技树节点。

检索机会是阶段解析产生的可消费状态，不是可交易货币。实体解析数据、通用原胚和专属原胚是实际生产物品，也不与三类文明资源互换。

稳定状态分为四层：

- 阶段状态：解析数据进度、已生成机会和可用机会。
- 协议状态：是否发现和永久完整度。
- 配方状态：累计实际产出成功次数，用于校准运行控制。
- 文明状态：科技点、科技节点、成就和恢复进度。

定义目录不进入存档；玩家状态进入存档；运行缓存由稳定状态投影生成。任何系统都不得把同一事实同时保存在多个权威状态中。

## 4. 文明解析与协议检索

数据中心内的残缺 AI 是文明档案管理核心，只负责维护索引、校验权限和调度设施。它不能读取协议正文，不能自行创造科技，也不能绕过玩家产线生成解析成果。

六色矩阵对应六个连续主线阶段。解析塔输出对应阶段的实体解析数据，上传后积累该阶段的检索机会。机会成本可以随阶段内生成次数增加，但增长必须服务节奏控制，不能让后期协议在有限游戏时间内事实上不可恢复。

协议检索提供三种玩家决策：

- 广域检索：不消耗额外货币，在当前阶段全部可行动协议中随机结算。
- 方向检索：消耗残片，把候选限制到指定配方方向，但仍保留方向内随机性。
- 锚定检索：消耗记忆源点，固定一个未完成协议，并保证该协议被发现或推进。

检索必须遵守以下机制契约：

- 没有可行动协议或可执行深层解析时，不消耗机会和策略货币。
- 普通检索允许无效响应，但无效响应必须提供残片收益并受到保底约束。
- 锚定检索不能消耗记忆源点后只产生无效响应或无关协议结果。
- 已发现且未完成的协议可以设为优先目标，但普通广域和方向检索不能完全消除其他候选。
- 批量检索必须严格等价于按相同顺序逐次执行单次检索，每一步都更新候选池、货币、保底和完整度。
- 阶段主协议全部完成后，该阶段机会转入深层解析，而不是继续返回无意义的协议结果。

## 5. 协议、配方与阶段

协议是旧文明留下的生产规则，不是可反复升级的卡牌。协议首次发现后永久保存进度，达到完整状态后取得并开放对应配方；完整度阈值由对应规格统一定义。

进入随机协议目录的内容仅包括：

- 可持续消耗原矿的资源复制配方。
- 同一工业链或用途链中的便利性转化配方。
- 满足培养资格后的实体塔返祖配方。

以下内容属于基础设施，不进入随机协议池：

- 通用原胚随机培养。
- 专属原胚稳定培养。
- 六色矩阵解析。
- 通用原胚谱系分化。

配方阶段按产物首次参与原版流程的阶段判断。不可自动采集的木材和植物燃料归电磁阶段；可燃冰允许进入能量阶段；必须依赖星际航行的其他珍奇矿物不得提前。高阶输出不能借助低阶输入提前开放；黑雾资源只有在玩家实际接触对应掉落后才进入协议池，并作为附属协议，不阻塞六阶段主线完成。

资源塔只复制可持续消耗的原矿资源，不复制临界光子、反物质或其他承担关键原版系统边界的产物。转化塔只提供工业链或用途链内的便利转换，不能发展成万能等价交换。

配方变体、新供应链和打包物只在基础配方分类稳定后逐族评估，不能为了内容数量批量复制一套镜像物品或配方。

## 6. 四塔职责与原胚体系

四类塔与四类配方职责固定：

- 交互塔：培养原胚、执行实体塔返祖、上传物品并连接数据中心。
- 解析塔：把矩阵转化为实体解析数据，并把通用原胚分化为专属谱系。
- 资源塔：复制可持续消耗的原矿资源。
- 转化塔：执行工业链或用途链中的便利性转换。

塔型和输入物品共同唯一确定配方。不能因为某类配方数量较多，就按数量机械拆出更多塔型。

原胚系统遵守以下契约：

- 通用原胚主要来自开采装饰物、异常信号和探索事件等非自动化入口。
- 通用原胚可随机培养为四类实体塔；专属原胚只稳定培养对应塔。
- 解析塔可以把通用原胚分化为四种专属谱系；取得主路锁定许可并完成配方校准后，玩家可以指定谱系。
- 实体塔返祖只产生对应专属原胚；返祖协议必须在对应专属培养达到资格后才进入检索池。
- 返祖协议是后期可选附属协议，不能阻塞电磁阶段主线。

开局必须提供足够多的通用原胚，确保随机结果不会阻断第二座交互塔和首座解析塔。遗迹只要求玩家手动重建交互塔，其他建筑保持可观察的完整运转结构。首轮教学必须让玩家看到“培养第二座交互塔，再把第一座塔的正面产物接入第二座塔正面完成上传”的完整闭环。

## 7. 远古科技与运行控制

科技树只消耗远古文明科技点。四条稳定主干按交互塔、解析塔、资源塔和转化塔排序；每条主干恢复同一组塔型通用能力，玩家在前中期选择优先方向，当前存档最终可以取得全部主干。

主干能力按以下顺序形成清晰的运行成长：

- 流动输出堆叠。
- 产物输出堆叠。
- 产物缓存满载时继续分馏。
- 主路锁定。
- 副产物弃置。

前两项和持续分馏是塔型共享能力。主路锁定与副产物弃置必须同时满足三层许可：对应塔型科技已恢复、当前配方累计实际产出成功完成校准、当前实体塔保存了具体设置。

运行控制遵守以下边界：

- 主路锁定只从主产物集合选择目标，不改变副产物。
- 副产物弃置只销毁副产物，不补偿主产物、成功率、输入、增产点、速度或其他收益。
- 配方校准只累计实际产生至少一个产物的成功；判定成功但产物数为零的批次不能提前推进校准。
- 实例设置必须随存档、复制粘贴、蓝图和联机同步。
- 文明业务不能进入逐物品分馏热路径；热路径只读取文明状态生成的运行缓存。

主干承载塔型共享能力和核心特质；模组兼容、配方族和配方变体放在主干外分叉。分支节点可以要求基础协议、阶段完成、原版科技或生产条件，但不能创建第二套不可回收科技货币，也不能让玩家永久失去其他方向。

## 8. 成就与长期目标

成就是当前存档内的固定生产里程碑，不消耗科技点，也不替代协议和科技树。

- 条件由真实生产、协议恢复、阶段完成和科技投入自然推动。
- 完成后自动生效，可以定向增强配方族或提供轻量全局加成。
- 成就奖励必须与完成时机匹配，不能让新档继承决定性生产强度。
- 成就和科技节点彼此独立；任务式目标不应被强行挂到科技树上。
- 成就定义和排序应服务玩家理解当前进度，而不是按代码模块机械分组。

普通成就不跨存档提供决定性强度。跨存档内容若未来存在，只能承担发现记录、背景、外观或不改变核心产线结果的便利功能，并需另行确认设计边界。

## 9. UI、教学与信息反馈

主面板长期保留生产、文明解析、资源、恢复手册、图鉴和设置等可持续使用的页面；一次性流程不得挤占长期分类。文明解析分类提供四个长期入口：

- 文明总览：展示阶段解析数据、检索机会、发现和完成情况。
- 协议恢复：选择阶段、检索策略、方向、锚定目标、优先协议和批量次数，并反馈每次结算。
- 远古科技树：展示科技点、四条塔型主干、前置条件和已恢复能力。
- 文明成就：展示当前存档里程碑、进度、完成状态和固定奖励。

UI 只负责展示、选择和确认。它可以提交文明动作，但不能绕过业务规则直接生成物品、写入协议完整度或修改分馏结果。

教学必须优先解释玩家当前闭环和下一步缺口，不在界面中堆叠实现说明。恢复手册负责长期可查的系统说明；首次入口提示只负责把玩家引向对应页面。

旧抽取、成长商店、市场交易和旧线性配方成长已经移除，不得再注册旧页面、旧存档块或兼容迁移入口。

## 10. 存档、联机与版本迁移

文明定义、配方定义和科技定义不进入存档；玩家取得的阶段、协议、科技、成就和配方校准状态进入存档；运行缓存只在初始化和导入后重建。

联机采用主机权威模型：

- 客户端只能提交受约束的动作请求。
- 主机验证请求、结算资源和进度，然后广播完整权威状态。
- 客户端不能发送全量文明快照覆盖主机。
- 自动上传、成就完成和玩家加入等会改变或需要补发状态的节点由主机广播。

实例运行设置必须和文明状态采用一致的权威边界，不能出现客户端先行结算后再尝试覆盖主机的路径。

FE 2.x 迁移只处理有明确现役对应物的建筑、模型、物流配方、原胚、科技和运行状态。废弃机制不得映射成新机制；不存在真实对应物的旧内容应被明确舍弃，而不是为了保留存档数值强行创造补偿关系。

版本迁移必须幂等。没有真实旧存档和蓝图样本时，只能声明结构验证和人工映射复核，不能声明实档迁移通过。

## 11. 全局红线

- 不跳过原版关键阶段。
- 不让随机性决定核心内容是否永久可得。
- 不让自动化规模无限放大一次性抽奖价值。
- 不让 UI、任务、成就或商店替代真实产线。
- 不让残片、记忆源点和远古文明科技点互相兑换。
- 不让资源复制替代戴森球、射线接收、质能转换或其他关键原版生产边界。
- 不让转化配方成为普通物品间的万能等价交换。
- 不让文明业务对象进入分馏逐物品热路径。
- 不为每个原版物品复制一套新增中间物。
- 不恢复旧建筑等级、经验、突破、献祭、裂变、共振、自动喷涂池或旧配方成长路径。
- 不恢复 S/A/B/C 稀有度、十连、出金动画、限时池、每日次数、登录奖励或错过不返内容。
- 不引入事件总线、依赖注入容器或为未来假设建立复杂策略层。
